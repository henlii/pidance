# v0.2.49

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 多实例：只有「对端正在跑」才显示占用

以前在另一个实例里**打开**一个会话（页面挂着、没发消息），这边就显示被占用。

根因是状态投影把「对端持有 writer 租约」直接当成了「被占用」。而按既有取舍
（`pidance-runtime` skill：startup host 只要浏览器还挂着就保留，有订阅者时连 idle 回收都不排），
打开会话会留下一个**空闲的 live host** —— 它确实仍是 writer，于是被显示成占用。

现在把两个概念分开，租约里带上真实运行态（`RunningLease.running`，由 8 秒心跳按
实际运行集合刷新）：

- **写保护**继续看「有没有活着的 writer」（`isRunningLeaseHeldByOther`）：空闲 writer 也拒，
  acquire 与 409 的语义完全不变，不会出现双写；
- **界面占用**改看 `isRunningLeaseActivelyRunningByOther`（进程活着 **且** `running === true`）。
  缺 `running` 字段的旧租约按「没在跑」处理 —— 宁可少显示锁定，也不误报占用。

应用点：`/api/sessions/[id]/lock`（锁定条与发送门禁的探针）、跨进程 watch 的 locks 帧。

实测（服务端）：`running:false` → `{lockedByOther:false}`；`running:true` → `{lockedByOther:true}`；
旧租约（无字段）→ `false`。

### 验收范围

`tsc --noEmit`；`npm test` 2773 项（含新增的「空闲 writer 不算占用」「旧租约不算占用」）；
31416 部署后按上述三种租约状态直接验证 `/api/sessions/[id]/lock` 的返回。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### Multi-instance: only a peer that is actually running shows as busy

Previously, merely **opening** a session in another instance (page left open, no message sent)
made this instance show it as occupied.

The status projection treated "the peer holds a writer lease" as "occupied". Given the existing
trade-off (see the `pidance-runtime` skill: a startup host is kept while a browser stays attached,
and no idle reclamation is scheduled while there are subscribers), opening a session leaves an
**idle live host** — it really is still the writer, so it showed up as occupied.

The two concepts are now separated by recording the real running state in the lease
(`RunningLease.running`, refreshed by the 8s heartbeat from the actual running set):

- **write protection** still keys off "is there a live writer" (`isRunningLeaseHeldByOther`):
  an idle writer is refused just the same, so acquire/409 semantics are unchanged and no double
  writes can happen;
- **UI occupancy** now keys off `isRunningLeaseActivelyRunningByOther` (process alive **and**
  `running === true`). Leases without the field are treated as "not running" — better to under-report
  a lock than to claim one that is not there.

Applied at `/api/sessions/[id]/lock` (the probe behind the lock bar and the send gate) and the
cross-process watch's locks frames.

Measured against the server: `running:false` → `{lockedByOther:false}`; `running:true` →
`{lockedByOther:true}`; a legacy lease (no field) → `false`.
