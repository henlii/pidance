# v0.2.44

## 中文

这一版把**扩展面板**的交互补齐了：看得见的东西现在都能点、都能按、都能输。

### 面板选项/问卷：看得见就能用

0.2.42 修的方向是错的（把面板自己的键盘捕获元素排除在「DOM 归属」之外，等于让按键窗口抢得更彻底）。
这版改成两层：

1. **面板守住键盘**：面板显示期间，焦点一旦落到面板之外就立刻收回面板的输入区。以前你在面板弹出来后
   只要在页面上点过一下别处，方向键和回车就**完全没反应**——这正是「面板看得见、用不了」。
2. **选项可点**：面板正文做了行级语义识别——边框换成 CSS 细线、加粗短行当标题、编号行或带光标标记
   （`❯`/`→`）的一组行识别成**可点选项**，用应用风格高亮（跟随明暗）。点一下就提交，不用再去按方向键。

识别是保守的：有边框、没有光标、只有一项、缩进不齐、像表格 —— **一律不猜**，按原样渲染。面板页头有
**「切回原样」**开关。

### 插件原语：直接设置，不再靠模拟按键

插件用 pi-tui 原语画界面时（`SelectList`、`Input`），壳会走一遍组件树认出来（只用公开接口，不碰私有字段）：

- **`SelectList`**：点网页第 N 项 = **直接设置选中项** + 确认，一条命令。比合成 N 次方向键更准 ——
  合成按键在插件中途重渲染时可能点错项（旧路径仍保留作兜底）。
- **`Input`**：渲染成**真输入框**。打字写回组件，回车交给插件的 `onSubmit`；初值从组件读，刷新后仍在。

真机验证用的是**真实的 pi-tui 组件**（不是仿造对象）：点第 3 项 → 插件选中「丙」并回调；输入框打字 →
面板正文同步变化 → 回车触发插件提交。

### 插件渲染的块默认折叠

插件条目渲染器的输出（如 `subagent-notify`）此前**无条件全量上屏**，既没有折叠分支、页头的折叠按钮也把它排除在外，
所以这类块永远铺满整屏。现在按统一规则：收起显示首行、点开看全部；只有一行时不折叠。

### 插件面板按自己声明的宽度渲染

插件声明 24 列的面板，以前正文按全局列宽排版、盒子却更窄，**必然出现横向滚动条**（盒子的 `ch` 是容器字体量的、
正文自己还有内边距）。现在数值宽度按列渲染：实测插件恰好画满时文本宽 = 可见宽、无横向滚动条。
插件真的画宽了仍保留滚动条（不裁切、不换行）。

### 手机端按键条

窄视口 + 插件面板占着键盘时出现一条 6 键按键条（↑↓←→⏎Esc，44px）：点屏幕 ↓ 移动选项、⏎ 确认。
桌面与没有插件界面时不显示。

## English

This release completes the **extension panel** interaction story: what you can see, you can now click, press and type into.

### Panel options and questionnaires are usable again

0.2.42 went the wrong way (it excluded the panel's own keyboard-capture element from "DOM-owned", which let the key
router win even harder). This release does two things instead:

1. **The panel keeps the keyboard.** While a panel is shown, focus that lands outside it is returned to the panel's
   input area. Previously, clicking anywhere else on the page left arrow keys and Enter doing nothing at all —
   the panel was visible but unusable.
2. **Options are clickable.** Panel bodies get line-level semantic detection: borders become CSS hairlines, short bold
   rows become headings, and a numbered group or a group marked by a cursor (`❯`/`→`) becomes a **clickable option
   list** highlighted with app theming. One click submits; no arrow keys required.

Detection is conservative: panels with borders, without a cursor, with a single item, with uneven indentation, or
table-like stay raw. The panel header has a **"plain view"** toggle.

### Plugin primitives: set state directly instead of faking keys

When a plugin draws with pi-tui primitives (`SelectList`, `Input`), the shell walks the component tree and recognises
them (public API only, no private fields):

- **`SelectList`**: clicking web option N **sets the selection directly** and confirms, in one command. That is more
  accurate than synthesising N arrow presses, which can land on the wrong item if the plugin re-renders mid-sequence
  (the old path stays as a fallback).
- **`Input`**: rendered as a **real input box**. Typing writes back into the component, Enter reaches the plugin's
  `onSubmit`, and the initial value is read from the component and survives a reload.

Verification used **real pi-tui components**, not stand-ins: clicking the third option made the plugin select 丙 and
fire its callback; typing in the web input updated the panel body; Enter triggered the plugin's submit.

### Plugin-rendered blocks collapse by default

Entry-renderer output (such as `subagent-notify`) used to be printed in full unconditionally — there was no collapse
branch, and the header toggle explicitly excluded it — so those blocks always filled the screen. They now follow the
same rule as every other block: collapsed shows the first line, expanding shows everything, and a single-line block
does not collapse at all.

### Panels render at their declared width

A panel declaring 24 columns used to lay its text out at the global width while its box was narrower, so a horizontal
scrollbar was unavoidable (the box measured `ch` in the container font, and the body had its own padding). Numeric
widths are now rendered per column: measured, text width equals visible width with no scrollbar when the plugin fills
exactly its declared columns. Scrollbars stay for plugins that genuinely overdraw — no clipping, no wrapping.

### Mobile key bar

On a narrow viewport, while a plugin panel owns the keyboard, a 6-key bar appears (↑ ↓ ← → ⏎ Esc, 44px): tap ↓ to move
the selection, ⏎ to confirm. It is not shown on desktop or when no plugin surface is present.
