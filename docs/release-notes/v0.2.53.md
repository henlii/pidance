# v0.2.53

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、工具输出不再把事件循环打满（31415 那次卡死的根因）

一个 55 万字符的工具输出，每帧渲染要 **262ms**，而节流间隔是 100ms —— 每秒欠 3 秒，事件循环被
占满，定时器、HTTP、socket 读取全部饿死（实测：固定间隔下渲染占用 98% 墙钟，心跳 60 次只跑到 13 次）。

三处一起改：

- **按开销限流**：渲染间隔 = max(100ms, 上次渲染耗时 ÷ 0.25)，渲染最多占四分之一墙钟（占用 98% → 26%，心跳 45/60）。
- **按增长量重渲**：流式 partial 只在载荷涨了「一档」才重渲（档位 = max(1KB, 10%)），整条流的渲染次数从「时长 × 10 次/秒」降到 O(log n)。
- **帧只发增量**：插件渲染行与工具原始输出都改成只发新增那一段（原始输出 `partialResultDelta`、渲染行 `renderedLinesAppendFrom`），单帧从 1MB 量级降到数百字节；原始输出在预算内整帧不推。

同时把渲染上限从 500 行 / 200KB 提到 **20000 行 / 4MB**（事故里那张 8360 行的卡片现在能完整画出），
超过上限不再静默回退原文，而是明说「输出过大，未渲染成卡片，下面是原文」。

### 二、扩展面板（插件 UI）

- **统一落到会话区下方**：以前没有 `overlayOptions` 的 `custom` 面板会整屏替换会话区、留一大块空白；
  现在两种 custom 与阻塞对话框共用会话区下方那一个插槽（TUI 里非 overlay 的 custom 替换的是 editor 区域，
  对应 Web 的输入区，这个位置更贴近原语义）。
- **标题取插件自己画的标题行**：`/advisor-models` 第二步不再看起来像「回到第一步」——标题直接是
  「Select Advisor Model」等插件画的英文问题；识别不到才退回「扩展面板」。
- **select / confirm 交给 SDK 选择器渲染**：服务端实例化 SDK 自带的 `ExtensionSelectorComponent` 渲染成终端行，
  与插件面板同一套观感（可选项目再是原生按钮；三条代价已在 UI 对照文档里写明）。
- **高度可拖到顶满会话列**：面板最大高度改成 100%，折叠收到最左侧独立按钮（点标题不再折叠），
  按住标题上下拖即可调高；复制/输入法改成图标按钮，尺寸与按键条一致。
- **面板占屏时，插件读到的是面板自己的尺寸**：以前插件的「终端」尺寸取自会话区滚动容器，
  面板一拖大滚动容器就变小，按行裁切的插件（如提问面板）跟着少画几行 —— 现在改成面板正文自身的尺寸，拖大就是变大。
- **手机端**：面板页脚加「输入法」入口，可以给 TUI 面板里的输入框打字。

### 三、消息导航跳转：只加载到目标那一小段

以前点历史消息要按固定页宽（500 条可见消息）一页页往上补，跳到很早的消息会补满整条会话（实测 2375 条、
约 9 秒）。现在服务端按 entryId 精确取 `[目标, 当前窗口起点)` 这一段（`sliceContextRange`，预留 20 条余量），
一次请求到位：跳最近的一段只要 1 个请求、约 100ms、26KB。目标已在已加载窗口里时不做任何加载。

### 四、侧栏

- **聊完就重排**：消息列表的跨进程广播原先只认「有哪些会话文件」，在已有会话里聊完一句（改的是文件内容）
  不会触发，侧栏不把这条排到项目最上面，得切页面或刷新。现在内容指纹（路径 + mtime + size）也参与，
  但要求**稳定一轮**才广播：一直写（正在跑）不刷屏，停笔补一次。
- **未读不再「看完了又变未读」**：未读时钟的合并只取了「localStorage 缓存 ∪ 服务端」，会把本端刚设的
  「已读」盖回旧值；现在三路并集（内存 ∪ localStorage ∪ 服务端），刚跑完的会话就是已读。

### 五、文件编辑器：查找替换

Ctrl/Cmd+F 在编辑器里打开查找（拦住浏览器页面查找）：匹配计数、上一个/下一个（Enter / Shift+Enter）、
区分大小写、替换一处、全部替换。替换走编辑器状态机（脏标记、撤销、外部冲突检测、保存流程照旧），
一次替换 = 一步撤销；替换串里再出现查询串不会被二次替换。

### 六、其他

`/compact` 后静默重载会话，不再让整个会话区重新加载。

### 验收范围

`tsc --noEmit`；`npm test` 2810 项；31416 实测：渲染占用 98% → 26%（`scripts/verify-render-livelock.mjs`）、
增量帧单帧约 330 字节且 from 链严丝合缝、面板三档标题与尺寸、跳转 1 个请求到位、
侧栏空闲 45 秒 0 次广播、编辑器查找替换两轮（桌面 + 390x844）、未读时钟单测复现修复前后差异。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Tool output no longer saturates the event loop (the root cause of the 31415 hang)

A 550k-character tool output cost **262ms** to render while the throttle interval was 100ms — three
seconds owed per second, so timers, HTTP and socket reads starved (measured: 98% of wall clock spent
rendering at a fixed interval, heartbeat fired 13 of 60 times).

Three changes together:

- **Cost-based throttling**: render interval = max(100ms, last render cost ÷ 0.25) — rendering may use at
  most a quarter of wall clock (98% → 26%, heartbeat 45/60).
- **Render on growth only**: a streaming partial re-renders only after the payload grows by a band
  (max(1KB, 10%)), turning O(duration × 10/s) renders into O(log n).
- **Delta frames**: both the plugin-rendered lines and the raw tool output now ship only the newly
  appended part (`renderedLinesAppendFrom`, `partialResultDelta`), cutting a frame from ~1MB to a few
  hundred bytes; partial frames inside the budget are dropped entirely.

Render caps were raised from 500 lines / 200KB to **20000 lines / 4MB** (the incident's 8360-line card
now renders in full), and oversize output is announced ("too large to draw as a card, showing raw text")
instead of silently falling back.

### 2. Extension panels

- **One slot below the chat area**: a `custom` panel without `overlayOptions` used to replace the whole
  transcript and leave a large blank area; both custom kinds and blocking dialogs now share the slot
  below the chat (in the TUI a non-overlay custom replaces the editor area, i.e. the input area on Web).
- **Title comes from the plugin's own heading line**: step two of `/advisor-models` no longer looks like
  a repeat of step one.
- **select / confirm are rendered by the SDK's own selector** on the server, matching the plugin panel look.
- **Drag the panel up to the full session column**: max height is 100%, collapse moved to the leftmost
  button (clicking the title no longer collapses), copy/keyboard became icon buttons.
- **Plugins measure the panel, not the transcript**: a panel that crops by rows no longer loses lines
  when you enlarge it.
- **Mobile**: a keyboard entry in the panel footer for typing into TUI panels.

### 3. Message navigation jump loads only the needed range

Clicking a historical message used to page up in fixed 500-message chunks (a far jump loaded all 2375
messages, ~9 seconds). The server now slices exactly `[target, current window start)` by entryId
(`sliceContextRange`, 20-message margin): one request, ~100ms, 26KB for a nearby target.

### 4. Sidebar

- **Reorder on completion**: the cross-process broadcast only recognised "which session files exist", so a
  finished chat in an existing session (content change, same path) never re-sorted the list. The content
  fingerprint (path + mtime + size) now counts, but only after it **settles** — a session that is still
  writing does not spam refetches.
- **Unread no longer flips back**: the clock merge only used "localStorage ∪ server" and could overwrite a
  just-read completion with older values; it now unions memory ∪ localStorage ∪ server.

### 5. File editor: find and replace

Ctrl/Cmd+F opens in-editor find (browser page find is intercepted): match counter, next/previous
(Enter / Shift+Enter), match case, replace one, replace all. Replacement goes through the editor state
machine (dirty flag, undo, external-conflict detection, save flow unchanged), one replacement is one
undo step, and replacing does not re-match inside the inserted text.

### 6. Other

Silent session reload after `/compact` instead of reloading the whole chat area.

### Verification

`tsc --noEmit`; `npm test` 2810 tests; measured on 31416: render duty 98% → 26%
(`scripts/verify-render-livelock.mjs`), delta frames ~330 bytes with an exact `from` chain, panel titles
and sizes across three steps, a jump served by one request, zero broadcasts in 45 idle seconds, editor
find/replace on desktop and 390x844, and a unit test reproducing the unread regression before/after.
