# v0.2.33

包：`@henlii/pidance` · CLI：`pidance`

## 中文

### 聊天滚动与顺序

- **自动跟随不再被选区永久卡住**：`pinToBottom` 里「页面上存在选区就返回」是粘性守卫——用户选中一段工具输出后，后续每次钉底都被挡掉，而它是唯一的 scrollTop 写入方，表现为「多输出几块工具内容后自动跟随就此失效」，连「回到底部」也点不动。改为只保留指针按下中的即时守卫；阅读意图仍由跟随状态兜（拖选在 pointerup 时置为 released，released 的调用点本来就不 pin）。
- **流式期间发出的引导不再跳到该组上方**：引导的乐观气泡在发出当刻进时间线，而被它打断那一步的 assistant 记录随后才到，直接追加会把引导从「组下方」翻到「组上方」并一直保持。现在引导记录带「发出时本步还在流式」标记，本步记录落盘时插到它前面（磁盘顺序也是 step 内容在前）。
- **左侧导航条跟到最后一条**：贴底时按「视口顶部之前最后一条提问」推会落到倒数第二条（末轮很短时尤其明显），改为贴底且在最新一段时当前项就是最后一条；跟随重定位改由列表布局/内容变化驱动（原先只在 props 身份变化时跑一次，首帧未布局就再也没有第二次），并修掉列表 scroll 事件里重定位每帧重启动画、永远走不到位的问题。

### 后台提问

页面在后台期间 SSE 不自动重连，`extension_ui_request` 丢了就永久丢了；回到前台原来只重拉消息，状态快照里的待答请求没被应用，于是智能体在等回答、界面什么都不显示，只能刷新会话。现在统一走 `applyExtensionUiProjection`（status/widget/待答阻塞请求/custom 面板），接到热状态、切会话、reconcile 与切回前台四条路径。

### 侧栏项目模型

`addedProjectRoots` + `closedProjectRoots` 合并为单一 `projectRoots`：**只有列表里的项目显示在侧栏**（当前选中的项目例外），关闭项目 = 从列表移除，重新添加同路径即恢复。最近/置顶不再按项目过滤（未加入列表的项目里的会话仍可从最近区进入）。旧数据按「可见集合 = added − closed」迁移，并做一次性种子（按有会话的项目补齐，累积到会话列表权威加载完才收尾）。

### 项目信任

主 Agent 走同进程 SDK、本来不做信任判定；subagent 走 `pi` CLI 子进程会真的判定：cwd 有需要信任的项目资源、`trust.json` 里没有条目时是 ask，而子进程没有 UI → false，项目技能/扩展在子代理里整体缺失。现在信任面与侧栏项目**一一对应**：列表里的项目各写自己的精确条目（祖先已给 true 也写），关闭即删掉它那条，启动按列表回填；分支工作树建在仓库旁、拿不到项目根条目，所以创建时写、删除时撤。写入统一走 SDK 的 `ProjectTrustStore`，与 pi CLI 共用同一把锁。

### 合并进来的改动

- **添加项目流程**：弹窗路径自动跟随；缺失目录确认创建后进入引导页；分支名行去掉运行中状态。
- **设置项**：会话页字段/选项文案中英补齐，清掉硬编码中文与裸键名；添加供应商面板按内容区定尺寸，左上角「返回」改「取消」。
- **登录设备记录**：同一浏览器只占一条（原实现每次登录取新 jti 入库、登出只清 cookie，实测堆到 321 条）。
- **模型测试按钮**：不再把服务端 500 的纯文本当 JSON 解析错误显示；服务端错误文案带上 `error.cause`（拒连/DNS/TLS 可辨）。

### 其他

- 移除 `scripts/verify-installed-render-bridge.mjs`（依赖本机已装插件的手工验收，不是可重复的自动验收）及其 npm 脚本。
- SSE 回放脚本按同一口径读取 31416 密码（原先只认环境变量，在开启 UI 锁的 31416 上必然 401）。

### 已知边界

- **信任继承**：Pi 的查找规则是「最近祖先生效」。若列表里同时有父目录（例如家目录）和它的子项目，关闭子项目只会删掉它自己那条，效果上仍受信；按产品决定不做 `false` 覆盖。要严格生效就把父目录也从列表移除。
- **新设备迁移**：服务端偏好仍是旧模型（没有 `projectRoots`）且浏览器全新（无 localStorage）时，一次性种子不会触发；任何一台已迁移的客户端写过一次后即不受影响。
- 工作树在 Pidance 之外被手工删除（`git worktree remove`）时，其信任条目不会自动撤销。

验收：`npm run check`（typecheck + lint + 1658 单测全过）；浏览器回归——批量工具块跟随 8/8、引导顺序 1/1、导航条 3/3、收尾滚动 5/5、后台提问 1/1、SSE 回放 1/1；项目信任在真实 31416 上验证了「加入→写条目、关闭→删条目、重新加入→写回」且文件逐字节还原。

## English

### Chat scrolling and ordering

- **Auto-follow is no longer wedged by a text selection**: `pinToBottom` treated any `Range` selection on the page as a permanent stop. Once a user selected part of a tool output, every subsequent pin was skipped — and the pin is the only writer of `scrollTop`, so following died for the rest of the session and even "back to bottom" did nothing. It now only defers while a pointer is held down; reading intent is still carried by the follow mode (a drag-selection flips it to released at pointerup, and released call sites never pin).
- **A steer sent mid-step no longer jumps above that step's group**: the optimistic bubble entered the timeline immediately, while the interrupted step's assistant record arrived later and was appended after it — flipping the steer from below the group to above it, permanently. The steer record now carries a "sent while this step was streaming" mark, and the step record is inserted before it (which also matches disk order).
- **The left message rail follows to the last item**: at the bottom it used to resolve "the last question before the viewport top", which lands on the second-to-last item when the last turn is short. It is now the last question whenever the viewport is at the bottom of the live tail; re-centering is driven by list layout/content changes instead of one-shot prop identity, and the rail no longer restarts its own scroll animation every frame.

### Background questions

While the page is hidden the SSE stream does not auto-reconnect, so a lost `extension_ui_request` was lost for good; returning to the tab only refetched messages, leaving the pending request unapplied — the agent waited for an answer while the UI showed nothing until a session reload. State snapshots now go through one `applyExtensionUiProjection` (status/widget/pending blocking requests/custom panel) on the hot-state, session-switch, reconcile and tab-return paths.

### Sidebar project model

`addedProjectRoots` + `closedProjectRoots` collapse into a single `projectRoots`: **only listed projects appear in the sidebar** (the currently selected project is the exception), closing a project removes it from the list, and re-adding the same path restores it. Recent/pinned sessions are no longer filtered by project, so sessions of unlisted projects stay reachable. Legacy data migrates as `added − closed` plus a one-time seed (projects that have sessions, accumulated until the session list is authoritatively loaded).

### Project trust

The main agent runs in-process and never consults trust; subagents spawn the `pi` CLI, which does: with trust-requiring project resources and no entry in `trust.json` the decision is `ask`, and a non-interactive child resolves it to false — project skills and extensions silently disappear in subagents. Trust now mirrors the sidebar project list one-to-one: every listed project gets its own explicit entry (even when an ancestor already grants trust), closing it deletes that entry, and startup backfills the list. Branch worktrees live beside the repository and cannot inherit the project entry, so they are trusted on create and revoked on delete. All writes go through the SDK's `ProjectTrustStore`, sharing its lock with the `pi` CLI.

### Merged changes

- **Add-project flow**: the dialog path auto-follows, a missing directory can be confirmed and created before entering the guide page, and the branch-name row no longer shows a running state.
- **Settings**: session-page labels/options are fully localized (hardcoded Chinese and raw keys removed); the add-provider panel sizes to the content area and its top-left action is now "Cancel".
- **Login devices**: one browser keeps a single device record (previously every login inserted a new jti and logout only cleared the cookie — 321 records on this machine).
- **Model test button**: no longer reports a plain-text 500 as a JSON parse error, and server errors include `error.cause` (refused connection / DNS / TLS are distinguishable).

### Other

- Removed `scripts/verify-installed-render-bridge.mjs` (a manual check that depends on locally installed plugins) and its npm script.
- The SSE replay script reads the 31416 password the same way as the other browser scripts (it previously only honoured an environment variable and was guaranteed to fail with 401 against a locked 31416).

### Known limits

- **Trust inheritance**: Pi resolves the nearest ancestor entry. If both a parent (e.g. the home directory) and one of its children are listed, closing the child only removes its own entry and it stays effectively trusted; by product decision we do not write `false` overrides. Remove the parent from the list to make it strict.
- **Migration on a new device**: when the server prefs are still in the old shape (no `projectRoots`) and the browser has no localStorage, the one-time seed does not fire. Any already-migrated client fixes this for everyone.
- A worktree removed outside Pidance (`git worktree remove`) keeps its trust entry.

Verification: `npm run check` (typecheck + lint + 1658 unit tests) and browser regressions — batch tool-block following 8/8, steer ordering 1/1, message rail 3/3, settle scrolling 5/5, background question 1/1, SSE replay 1/1. Project trust was verified against a real 31416: add writes the entry, close deletes it, re-adding writes it back, with the file byte-identical afterwards.
