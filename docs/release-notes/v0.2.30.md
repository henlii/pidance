## 中文

### 消息发送与队列：一条消息只能有一个可执行持有方

此前运行中发送、引导、入队、整队转引导会互相改写类型、清掉还在队列里的内容、或把
A 会话的草稿写进 B。本版把所有权收口到服务端队列：

- 条目有稳定 `id` 与状态（`waiting` / `claimed` / `unknown`）；认领先落盘再投递，
  崩溃后 claimed 变为 unknown，**不自动重发**。
- 整队转引导、召回是服务端用例（`dispatch_follow_up_queue` / `recall_follow_up_queue`），
  不再「先清队再发」的浏览器补偿。
- 写入结果分 `accepted` / `queued` / `rejected` / `unknown`；只有带权威快照的
  accepted 证明内容归队列。从未被受理的载荷才回草稿；unknown 留在队列侧待确认。
- 受理凭据 `admittedAttemptIds` 与队列同一次落盘，并出现在 SSE、写入回执、
  `queued` prompt 回执和 `get_state` 热投影上。缺字段保持账本；显式空数组才表示
  确实没有受理过。
- 对齐认条目身份，不拿正文当身份；同文两条是两条。权威快照一旦被采信，会给更早的
  未决提交定论，并把未结算整包重整成「当前权威条目 + 自己新增的载荷」。

图片随队列走引用（选图即上传），不把 base64 塞进 prefs。运行中可入队纯图。
缺图、读失败 fail-closed，不降级成「只发文字」。

已知限制（不当时未修缺陷）：无 id 的旧写入仍按正文+附件配对；跨崩溃不是
exactly-once（unknown 要用户处置）；多标签无头浏览器未做，语义由 Host 交错测试覆盖。

### 附件入口与迟到的运行结束事件

- 粘贴 / 拖拽 / 选择器走同一入口：位图可在运行中入队；其它文件空闲时上传，
  运行中给出明确提示而不是没反应。
- 运行事件带本轮序号；迟到的上一轮 `agent_end` / `prompt_done` 不会把新一轮判成空闲。

### 桌面壳与终端（已在 main、随本版发布）

- Windows 桌面壳与主包同版本：只出 NSIS 安装版，按平台瘦身，托盘手动检查更新。
- `/api/pty` 偶发连上就断：清掉 Next 自挂的 upgrade 监听器；Windows 不再写死 `/bin/bash`。
- 桌面 CI 用当前分支的服务端候选包做验证，而不是 npm 上的上一版。

## English

### Message send and queue: one executable owner per message

Sending while running, steering, enqueueing, and flushing the queue as steer could rewrite
the send type, drop items still in the queue, or restore session A's draft into B. This
release makes the server queue the owner:

- Items have stable `id`s and states (`waiting` / `claimed` / `unknown`). Claim persists
  before delivery; after a crash, claimed becomes unknown and is **not** auto-resent.
- Queue-as-steer and recall are server commands (`dispatch_follow_up_queue` /
  `recall_follow_up_queue`), not a browser “clear then send” saga.
- Write outcomes are `accepted` / `queued` / `rejected` / `unknown`. Only `accepted` with
  an authoritative snapshot proves the queue owns the payload. Only never-admitted payloads
  return to the draft; `unknown` stays on the queue side as pending confirmation.
- `admittedAttemptIds` is persisted with the queue and included on SSE, write receipts,
  queued prompt receipts, and `get_state`. A missing field keeps the ledger; an explicit
  empty array means “nothing was admitted”.
- Alignment is by identity, not message text. Two identical texts are two items. Once an
  authoritative snapshot is adopted, earlier unsettled writes are resolved and in-flight
  envelopes are rebuilt as “current authoritative items + this write’s additions”.

Images in the queue are attachment references (upload on attach), not base64 in prefs.
Image-only items can enqueue while running. Missing files fail closed (no silent
text-only send).

Known limits (not open bugs): legacy writes without ids still pair by text+media;
crash recovery is not exactly-once (`unknown` needs explicit user action); there is no
dual-tab headless browser harness — multi-tab rules are covered by Host interleaving tests.

### Attachments and stale run-end events

- Paste / drop / file picker share one entry: rasters can enqueue while running; other
  files upload when idle, with an explicit error while streaming instead of a no-op.
- Run events carry a per-run sequence; a late previous `agent_end` / `prompt_done` cannot
  mark the new run idle.

### Desktop shell and PTY (already on main, shipping in this release)

- Windows desktop shell matches the main package version: NSIS installer only, platform
  prune, tray-initiated update checks.
- Occasional `/api/pty` drop-on-connect: remove Next’s extra upgrade listener; Windows no
  longer hard-codes `/bin/bash`.
- Desktop CI verifies with a candidate tarball of the current branch, not the previous
  npm release.
