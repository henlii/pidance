# v0.2.20

## 中文

### 核心变更：新会话与 host 生命周期重做
- **新会话一步创建**：发送首条消息改为单次请求（`POST /api/agent/new {type:"prompt"}`），不再「占位 intent → ensure → wake → prompt」多跳。真实会话 id 一次返回，消除了：侧栏先出现占位 A 又出现真实 B、切到 B 却显示 A 标题、发送后被拒只有乐观 1 条、刷新后会话消失等一系列竞态。
- **host 按端点订阅保活**：同一运行时的多标签页/多端打开同一会话可同时正常使用（含流式输出）；多个会话都能保活。只有**所有端点都关闭**该会话、且会话未在运行、无队列消息时，才在 **30 秒**后释放 writer；SSE 心跳 10 秒一次。
- **跨进程/跨运行时互斥不变**：其他程序正在使用的会话仍显示「当前会话正由其他程序使用」，不会并发写同一 JSONL。

### 修复
- 会话执行完立即 dispose 导致顶部上下文占用 / 输入区下方 footer（扩展状态条、上下文信息）消失 —— 改为订阅驱动保活后不再出现。
- 切到本页刚创建的会话时的「加载中」闪白。
- 新会话首条消息偶发被 404/拒绝（ensure 与 prompt 两跳之间的空窗）。

### 备注
- 后台占用：网页切到后台时，只要该标签页仍保持 SSE 连接（浏览器后台标签默认仍运行定时器与网络），会话仍视为「被端点打开」；移动端浏览器若系统冻结后台页面导致 SSE 断开，会按「端点关闭」进入 30s 释放，回前台时自动重连并重新保活。运行中的会话不受影响（run 本身在服务端推进）。

## English

### Core: new-session creation & host lifecycle rework
- **One-shot new session**: first message now creates + prompts in a single request (`POST /api/agent/new {type:"prompt"}`), replacing the placeholder-intent → ensure → wake → prompt multi-hop. This removes: double sidebar rows (placeholder A then real B), switching to B but showing A's title, rejected sends leaving only an optimistic row, and sessions vanishing after refresh.
- **Endpoint-driven host keep-alive**: multiple tabs/clients of the same runtime can use the same session simultaneously (streaming included); multiple sessions stay alive. The writer is released only **30s after every endpoint closed** the session while it is idle (not running, no queued messages). SSE heartbeat every 10s.
- **Cross-process mutual exclusion unchanged**: sessions in use by another program still show "in use by another program" and are never written concurrently.

### Fixes
- Top-bar context usage and below-input footer (extension status bar / context info) disappearing immediately after a run finished.
- Loading-flash when switching to a session this page just created.
- Occasional 404/rejection on the first message of a new session (gap between ensure and prompt hops).

### Notes
- Background: a backgrounded tab keeps its SSE connection alive (browsers keep timers/network running for background tabs), so the session stays "open". If the OS freezes the mobile browser page and the SSE drops, the host enters the 30s release path and re-attaches on return-to-foreground. Running sessions are unaffected (the run progresses server-side).
