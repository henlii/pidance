# v0.2.26

## 中文

### 会话内容显示与发送链重构

会话消息的显示顺序与「发送后处理」长期依赖逐条补丁（历史上有十几次竞态修复），
本次按「一类事实一个 owner」重新收口。

- 消息列表改由运行时注册表唯一写入：视图不再直接改写消息数组，只订阅投影。
  归并（首页加载、上滚更旧历史、分支切换、乐观消息追加与回滚）统一在
  slot 自身的时间线上原子完成，不再依赖 React 状态更新的时序。
- 每条消息记录带稳定标识：确认与回滚不再依赖数组下标，也不再用正文文本做
  近似匹配，因此上滚加载更旧历史后不会出现消息错位或重复。
- 聊天列表用稳定标识做 React key，上滚加载更旧历史不再重挂载全部消息，
  折叠状态与文本选区得以保留。
- 队列改为「已确认基线 + 单个乐观值」并按会话分账：失败回滚退回最后一次被
  服务端接受的队列，而不是退回一份从未被接受的中间状态；并发入队不再互相覆盖。
- 模型与思考档的写入按操作代次串行：连续两次选择不会交错成「模型 B + 旧深度 A」，
  迟到的失败也不会抹掉更新的选择；磁盘被另一实例改动时以磁盘为准，不再把
  本页的旧选择写回去。

### 修复

- **同一会话收到两份事件流**：SSE 致命断线后运行时已安排重连，此时丢弃旧连接
  管理器未关闭它，重连会走出一条无人跟踪的流，导致事件重复投递。
- **空闲会话不释放写入租约**：视图订阅计数在待定会话与真实会话两个标识之间
  失配时，`viewAttached` 永远为真，空闲回收不触发，服务端 host 不退出、
  跨进程写入租约不释放，另一实例打不开该会话。
- **上下文比例在使用一段时间后整块消失**：服务端 host 空闲退出后不再返回热状态，
  此时改由最后一条带用量统计的助手消息兜底计算，压缩后的「未知」状态仍优先显示。

### 性能

- **补上 API 响应压缩**：Next.js 的 `compress` 只在其内置服务器生效，而 Pidance
  自管 TCP（为接管终端 WebSocket 升级），导致 API 与页面一直明文下发。实测
  `/api/sessions` 106.9 KB → 28.6 KB（-73%），`/api/preferences` -65%，页面 HTML -73%。
  压缩会跳过事件流（SSE 必须即时冲刷）、已编码响应、Range 请求与过小响应。
- **轮询轻量化**：运行态轮询新增轻量投影，省略几乎不变的 system 文令字段，
  单次 34.8 KB → 1.2 KB（-97%）。
- **会话列表去重**：修复一次进入页面会重复拉取整份列表（4 次 → 1 次）的问题。

### 界面

- **图片查看改为全屏遮罩**：点击消息中的图片后在整屏遮罩上显示原图（此前是
  输入框上方的内嵌面板，高度受限，看大图需反复缩放拖动）。支持滚轮/按钮缩放、
  拖动平移、双击、ESC 与点击空白处关闭、下载原图；窄视口与软键盘弹出时同样贴合。
  平移范围按图片实际渲染尺寸收敛，缩回 100% 即回到居中。
- **顶栏新增解码吞吐与首字延迟**：显示最近一轮的 tok/s（悬停可见完整读数）。
  算法与 DeepSeek Harness 的 turn-metrics 一致：解码时长不含首字等待、只用
  服务端上报的输出词元、按解码时长加权。首字延迟在起点未知时不显示。

## English

### Session rendering and send-path rework

Message ordering and post-send handling had accumulated over a dozen patch-level race
fixes. This release consolidates them around one owner per fact.

- The runtime registry is now the sole writer of the message list; the view only
  subscribes to a projection. Merging (initial load, loading older history, branch
  switch, optimistic append and rollback) happens atomically on the slot's own
  timeline instead of depending on React state-update timing.
- Every message record carries a stable identity, so confirmation and rollback no
  longer depend on array indices or content-text matching. Loading older history can
  no longer misplace or duplicate messages.
- The chat list uses stable identities as React keys, so prepending older history no
  longer remounts every message and no longer discards collapsed state or text selection.
- The follow-up queue is now "confirmed baseline + one optimistic value", accounted per
  session. A failed sync reverts to the last server-accepted queue rather than to an
  intermediate state the server never accepted, and concurrent enqueues no longer
  overwrite each other.
- Model and thinking-level writes are serialized per operation generation: two rapid
  selections can no longer interleave into "model B with stale depth A", a late failure
  cannot discard a newer selection, and an external change on disk wins instead of being
  overwritten by this page's stale choice.

### Fixes

- **Two event streams for the same session**: after a fatal SSE disconnect the runtime
  had already scheduled a reconnect; dropping the old connection manager without closing
  it let it reconnect into an untracked stream and deliver every event twice.
- **Idle sessions never released the write lease**: attachment accounting could be
  inflated when the pending session id and the real session id were both subscribed, so
  `viewAttached` never became false, idle reclamation never ran, the server host never
  exited, the cross-process write lease stayed held, and the other instance could not
  open that session.
- **Context usage disappeared after a while**: once the server host idles out it no longer
  returns hot state; usage is now derived from the last assistant message with token
  statistics, while an explicit "unknown" reading after compaction still takes precedence.

### Performance

- **API response compression**: Next.js `compress` only applies to its own built-in
  server, but Pidance owns the TCP socket (to handle the terminal WebSocket upgrade), so
  API and page responses were sent uncompressed. Measured: `/api/sessions`
  106.9 KB → 28.6 KB (-73%), `/api/preferences` -65%, page HTML -73%. Compression skips
  event streams (SSE must flush immediately), already-encoded responses, range requests,
  and very small responses.
- **Lighter polling**: the runtime-state poll gained a light projection that omits the
  nearly-constant system prompt field: 34.8 KB → 1.2 KB per request (-97%).
- **Session list de-duplication**: entering the page fetched the full list four times;
  it now fetches once.

### UI

- **Full-screen image viewer**: clicking an image now opens the original in a full-screen
  overlay instead of a height-constrained inline panel above the composer. Supports
  wheel/button zoom, drag-pan, double-click, ESC and click-outside to close, and original
  download; it also fits narrow viewports and on-screen keyboards. Panning is clamped to
  the image's rendered size, so zooming back to 100% recenters it.
- **Top bar shows decode throughput and time to first token**: the latest turn's tokens/s
  (full readings on hover). The algorithm matches DeepSeek Harness `turn-metrics`: decode
  time excludes first-token wait, only provider-reported output tokens are used, and the
  value is weighted by decode time. Time to first token is hidden when its start point is
  unknown.

## 安装 / Install

```bash
npm install -g @henlii/pidance
pidance
```

CLI 仅 `pidance`；默认端口 31415（本机回环）。
