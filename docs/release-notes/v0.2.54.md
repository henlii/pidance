# v0.2.54

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、排队消息不再丢（真丢过）

运行中排队一条消息，run 结束后它会**从队列里消失，而且从来没被发出去** —— JSONL 里查不到。
用 UI 输入框真发一次即可复现（服务端队列文件 `items=0`、revision 连跳两格，内容却不在会话里）。

日志实证的因果链：投递被受理（`accepted`）后旧实现立刻把条目出队 → 同一轮 `agent_settled`
的回收判定以为「没有待投递的队列」（条目已是 claimed 态，不算 waiting）→ 销毁 runtime →
那条 prompt 以 `SDK session is not alive` 异步失败，而条目早就没了。

现在把「已受理」和「已送达」分开：受理后条目留在队列里（claimed），看到那条 user 消息
真的落盘才出队；15 秒内没落盘（超时或异步失败）就原样放回队列，并给一条可见的错误提示
（“排队消息没送出去，已放回队列”）。送达确认窗口内也不回收 runtime，否则在途投递必死。
复跑同一个复现脚本：排队消息在 run 结束后落进 JSONL，队列随后自然清空。

### 二、会话里的块统一：可折叠 + 高度上限

除了你和助手的正文，其它块一律**可折叠且默认收起**：此前漏在规则外的扩展自记消息（纯文本
形态没有折叠箭头）、`!命令` 记录块、活动记录块、智能体自记的媒体块都补齐了。每个块的正文
也统一有高度上限（桌面 `min(320px, 45vh)`、窄屏 `min(240px, 32vh)`，块内滚动），压缩块与
分支摘要此前没有，现在也有了。你自己发的消息与附件照旧不折叠、不限高。

### 验收范围

`tsc --noEmit`；`npm test` 2814 项；31416 实测：排队消息复现脚本从「内容消失」变为
「落进 JSONL」；工具/思考块默认收起、会话区渲染正常；压缩/分支摘要展开态块内滚动。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Queued messages are no longer lost (they really were)

Queue a message while a run is in flight and it **disappeared from the queue without ever being
sent** — reproducible with a normal UI send (the server queue file went to `items=0`, the revision
jumped twice, yet the message never reached the session).

The cause, proven from logs: after delivery was accepted the old code removed the entry at once;
in the same `agent_settled` pass the teardown check concluded "nothing waiting to be delivered"
(the entry was `claimed`, not `waiting`) and destroyed the runtime; the prompt then failed
asynchronously with `SDK session is not alive` — with the entry already gone.

Acceptance and delivery are now separate: the entry stays in the queue (`claimed`) until the
corresponding user message is actually persisted, and if that does not happen within 15 seconds
(timeout or async failure) the entry is put back into the queue with a visible error notice.
The runtime is also kept alive while a delivery is unconfirmed. Re-running the reproduction script
now shows the queued message landing in the JSONL and the queue draining by itself.

### 2. Consistent blocks: collapsible and height-capped

Every block except your messages and the assistant's prose is collapsible and collapsed by default —
including the ones that were missed before (plain-text extension messages, `!command` records,
activity records, agent-attached media). Every block body is now height-capped
(`min(320px, 45vh)` desktop, `min(240px, 32vh)` narrow, scrolling inside), which the compaction and
branch-summary blocks previously lacked. Your own messages and attachments stay expanded.

### Verification

`tsc --noEmit`; `npm test` 2814 tests; measured on 31416: the queue reproduction turns from
"content disappeared" into "lands in the JSONL"; tool/thinking blocks collapsed by default with a
healthy transcript; compaction and branch-summary bodies scroll inside their cap.
