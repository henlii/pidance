# v0.2.43

## 中文

这一版把**扩展面板**这条线收干净了，并修掉两个你直接用得到的问题。

### 面板里的选项现在真的能点/能按了

前几版的毛病分两层，都修了：

1. **焦点一离开面板，按键就送给"全局监听器"而不是面板组件**。你在面板弹出来后只要在页面上点过一下别处，
   焦点就落到 `body`，此后方向键和回车**完全没反应** —— 面板看得见、用不了。现在面板显示期间会守住键盘：
   焦点一旦落到面板之外就立刻收回面板的输入区（焦点在面板里时不动它）。这与 TUI 里 overlay 拿到键盘后的
   行为一致。
2. **面板正文开始"网页化"**：边框换成 CSS 细线、加粗短行当标题、编号行 + `❯`/反显那组识别成**可点选项**
   （用应用风格高亮，跟随明暗）。点选项 = 合成方向键 + 回车，并且有两道自校验：发键前重读面板（内容变了就
   让位，绝不点错项）、发完方向键确认光标到了目标项才回车。面板页头有**「切回原样」**开关，随时能回到原始渲染。

识别是保守的：整行制表符才算边框；有边框、没光标标记、只有一项、缩进不齐、像表格 —— **一律不猜**，按原样渲染。
正文仍是等宽（插件靠它对对齐表格和方框）。

### 面板宽度按插件声明的来（横向滚动条消失）

插件声明 24 列的面板，以前正文按全局列宽（92/105 列）排版、盒子却更窄，**必然出现横向滚动条**。
原因是两处叠加：盒子的 `ch` 是**容器字体**量的（不是等宽正文的），而正文自己还有内边距。
现在数值宽度按列渲染：容器 `fit-content` 包住正文，正文用 `Nch` 定宽。实测插件恰好画满时
文本宽 = 可见宽、**没有横向滚动条**。插件真的画宽了仍然保留滚动条（不裁切、不换行）。

### 手机上终于能操作插件面板

软键盘产不出方向键，问卷/选择这类面板在手机上本来是**不可用**的。窄视口 + 插件界面占着键盘时，
底部会出现一条 **6 键按键条**（↑ ↓ ← → ⏎ Esc，44px 触摸目标，双语文案）：点屏幕 ↓ 就能移动选项，
点 ⏎ 就是确认。桌面与没有插件界面时不显示（不挡输入框）。

### 会话区布局按你的草图对齐

- 调宽手柄**上下贯通中间列全高**（会话内容 + 扩展 + 页脚 + 输入区），不再是只覆盖消息滚动区；
- 手柄与会话区**固定 16px**，与两端竖条**没有间距**（多出来的空白落在竖条与手柄之间，窗口先吃掉它）；
- 取消可调固定上限，最小宽度 **600**；会话区比该下限还窄时**不渲染手柄**；
- 三段（内容 / 扩展+页脚 / 输入）同宽同中心线；
- 设定值改按**像素**记忆：窗口缩小只影响显示，**不回写**设定值（窗口回来后恢复原宽度）。

### 另外

- 插件面板显示时输入区让位（与扩展对话框、编辑器接管一致）。

## English

This release closes out the **extension panel** line of work and fixes two issues you hit directly.

### Panel options are now actually usable

Two separate defects, both fixed:

1. **As soon as focus left the panel, keys went to the plugin's global listener instead of the panel component.**
   Clicking anywhere else on the page moved focus to `body`, after which arrow keys and Enter did nothing —
   the panel was visible but unusable. The panel now keeps the keyboard while it is shown: if focus lands outside
   it, focus is returned to the panel's input area (focus inside the panel is left alone). This matches the TUI,
   where an overlay takes the keyboard when it is shown.
2. **Panel bodies are now rendered as web content**: border rows become CSS hairlines, short bold rows become
   headings, and a numbered group with a `❯`/reverse-video cursor becomes a **clickable option list** (highlighted
   with app theming that follows light/dark). Clicking an option synthesizes arrow keys plus Enter, guarded twice:
   the panel is re-read before sending (if it changed, we stand down instead of clicking the wrong row), and after
   the arrow keys the cursor must actually be on the target before Enter is sent. The panel header has a
   **"plain view"** toggle back to the raw rendering.

Detection is conservative: only all-box-drawing rows count as borders; panels with borders, without a cursor
marker, with a single item, with uneven indentation, or table-like stay raw. Body text stays monospace, because
plugins rely on it for alignment.

### Panels render at their declared width (no more horizontal scrollbar)

A panel declaring 24 columns laid its text out at the global width (92/105 columns) while its box was narrower,
so a horizontal scrollbar was unavoidable. Two causes compounded: the box measured `ch` in the *container* font
rather than the monospace body, and the body had its own padding. Numeric widths are now rendered per column
(container `fit-content` around a body sized `Nch`). Measured: text width equals visible width with **no
horizontal scrollbar** when the plugin fills exactly its declared columns. Scrollbars are kept for plugins that
genuinely overdraw — no clipping, no wrapping.

### Extension panels are usable on phones

Soft keyboards cannot produce arrow keys, so questionnaire/select panels were simply unusable on mobile. On a
narrow viewport, while a plugin surface owns the keyboard, a **6-key bar** appears at the bottom
(↑ ↓ ← → ⏎ Esc, 44px touch targets, bilingual labels): tapping ↓ moves the selection, ⏎ confirms. It is not shown
on desktop or when no plugin surface is present.

### Session area layout now matches your sketch

- Resize handles span the **full height of the middle column** (messages + extension + footer + input);
- handles sit a fixed **16px** from the session area and have **no gap** to the side rails (surplus whitespace
  collects between the rails and the handles, and window shrinking consumes it first);
- the adjustable fixed maximum is gone; minimum width is **600**; when the session area is narrower than that,
  handles are not rendered;
- messages, extension/footer and input share one width and centerline;
- the stored width is now in **pixels**: shrinking the window only affects display and never rewrites the setting
  (widening it back restores the original width).

### Also

- The composer yields while a plugin panel is shown (consistent with extension dialogs and editor takeover).
