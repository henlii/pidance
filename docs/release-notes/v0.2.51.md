# v0.2.51

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 多实例：租约改为「执行互斥」，打开会话不再锁定

以前**打开**一个会话（哪怕是浏览历史、页面就那么挂着）就会占住写入租约，只要另一实例的
页面还开着，这边改思考档位/模型就一律被拒。现在租约的语义是**正在执行**：

- 打开 / 唤醒 / 浏览**不占租约** —— 多个实例可以同时打开同一会话、同时读；
- **执行中**才互斥（对方隐藏输入区）；**执行结束立即释放**，不再等 host 回收；
- 空闲时**任何实例都能改**思考档位与模型。

### 空闲时的改动会同步到其他实例

改档位/模型落盘后主动写一个「请重读」信号（`pidance-session-state/`），其他实例通过
fs.watch 即时收到、2 秒轮询兜底，页面跟着更新；本进程若正好持有该会话的**空闲** host，
会丢弃它的陈旧内存态，下次重建时从磁盘读到新值。正在执行的 host 不动。

状态优先级：**前端 < 后端 < 文件**（磁盘权威）。

### 思考档位：判据统一，被拒不再静默

之前输入区用 React 状态判断「是否在跑」，hook 用 registry 判断，两者不同源会留下空窗 ——
界面显示改动成功（连偏好缓存都写了），实际请求被静默拒绝，表现为「改成 high 没效果、
刷新后还是 max」。现在判据统一到 hook，且**偏好缓存只在真正生效后才写**；
被拒时弹出「运行中不能修改模型或思考深度」。

### 输入区：去掉每键两次强制重排

`onInput` 每次都 `height="auto"` + 读 `scrollHeight`（一次强制重排），`[value]` effect 里还有一遍。
两条路径现在共用判断，支持 `field-sizing` 时都不做 JS 测量。实测（流式输出期间）单次按键
尖峰 **203.8ms → 19.2ms**。另外修掉了 `handleFooterToggle` 导致的每秒 244 次无效重渲染。

### 验收范围

`tsc --noEmit`；`npm test` 2775 项；31416 实测：新建会话打开后无租约、执行中持有、结束即释放；
两次改档位产生两个 `session-state` 广播帧；输入区按键尖峰 19.2ms。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### Multi-instance: the lease now means "executing", not "I am the writer"

Previously merely **opening** a session (browsing history, or just leaving a page open) held the
write lease, so as long as another instance had the page open, changing the thinking level or model
here was refused. The lease now means **currently executing**:

- opening / waking / browsing takes **no lease** — several instances may open the same session and read it concurrently;
- mutual exclusion applies only **while executing** (the other instance hides its composer); it is **released the instant the run ends**, no longer waiting for the host to be reclaimed;
- while idle, **any instance may change** the thinking level and model.

### Idle changes sync to other instances

After a level/model change is persisted, a "please re-read" signal is written
(`pidance-session-state/`). Other instances pick it up immediately via fs.watch with a 2s poll
fallback and update their page; if this process happens to hold an **idle** host for that session,
its stale in-memory state is dropped so it re-reads from disk. A running host is left alone.

State precedence: **client < backend < file** (disk is authoritative).

### Thinking level: one source of truth, refusals are no longer silent

The composer used a React state to decide "is it running" while the hook used the registry — two
different sources left a gap where the UI showed the change as applied (even writing the preference
cache) while the request was silently refused, i.e. "I set high but it stays max, and after a
refresh it is max again". The decision now lives solely in the hook, the preference cache is written
**only after the change actually takes effect**, and a refusal shows
"Can't change model or thinking while running".

### Composer: two forced reflows per keystroke removed

`onInput` ran `height="auto"` plus a `scrollHeight` read (one forced reflow) on every keystroke, and
the `[value]` effect did it again. Both now share one check and skip JS measurement when
`field-sizing` is supported. Measured while streaming: peak per-keystroke latency **203.8ms → 19.2ms**.
Also fixed 244 useless re-renders per second caused by `handleFooterToggle`.
