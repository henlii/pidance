# v0.2.50

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。本版两处修复。

### 升级不再误报失败

手机上点升级，弹窗报「失败 / Error in input stream」，其实服务已经升到新版本了。

升级最后必然重启服务，那条 SSE 连接会被切断，浏览器抛
`TypeError: Error in input stream`。旧代码两层都漏了：读流没有捕这个异常（直接冒泡成
「升级失败」），而判断「是不是重启切断了流」用的是 message 关键词正则
`/network|fetch|abort|failed/i` —— 真实文案一个词都不匹配，于是即使走到判定也不会去等新版就绪。

现在读流异常时返回明确的 `status: "dropped"` 标记（不再靠猜文案），判定优先认这个标记
（与走到哪个 phase 无关），随后按**实际版本**判定：已是目标版本就是成功，没到就仍报失败。

### 输入框去掉每键两次强制重排

`onInput` 每次都 `height="auto"` + 读 `scrollHeight`（一次强制同步重排），`[value]` effect
里还有一遍 —— 等于一次按键重排两遍。两条路径现在共用同一个判断：浏览器支持
`field-sizing` 时都不做 JS 测量，高度交给 CSS。

实测（1280x760，模型流式输出期间）：单次按键 input→下一帧的延迟尖峰
**203.8ms → 19.2ms**，中位数 16.1ms。

另外给输入区加了 `memo`（父组件流式期间每帧重渲染会连带整棵输入区），
并把每帧都在变的 `sessionTokens` 节流到 1s，否则 memo 会被它打破。

### 验收范围

`tsc --noEmit`；`npm test` 2775 项；升级路径两条新单测（流被切断 + 版本已是目标版本 → 成功；
流切断但始终没到目标版本 → 仍失败）含反向验证；输入框指标用 agent-browser 在 31416 实测
（空闲与流式各 3 轮，各 12 次按键取中位与最大值）。

## English

Package `@henlii/pidance`, CLI `pidance` only. Two fixes.

### Upgrades no longer report a false failure

Tapping upgrade on a phone showed "失败 / Error in input stream" while the service had in fact
been upgraded.

The upgrade restarts the service at the end, which cuts the SSE connection and makes the browser
throw `TypeError: Error in input stream`. Two layers missed it: the stream reader did not catch
the exception (it bubbled up as "upgrade failed"), and the check for "did a restart cut the
stream" relied on a message keyword regex `/network|fetch|abort|failed/i` — the real text matches
none of it, so even the fallback never waited for the new version to come up.

The reader now returns an explicit `status: "dropped"` marker on a stream error (no more guessing
at prose), the check honours that marker regardless of phase, and the outcome is decided by the
**actual version**: already at the target version means success, otherwise it still reports failure.

### The composer no longer forces two reflows per keystroke

`onInput` ran `height="auto"` plus a `scrollHeight` read (one forced synchronous reflow) on every
keystroke, and the `[value]` effect did it again — two reflows per key. Both paths now share one
check: when the browser supports `field-sizing`, no JS measurement happens and CSS owns the height.

Measured (1280x760, while the model was streaming): the peak input→next-frame latency for a single
keystroke dropped from **203.8ms to 19.2ms**, median 16.1ms.

The composer is also wrapped in `memo` (the parent re-renders every frame while streaming, which
dragged the whole input area along) and `sessionTokens`, which changed every frame, is throttled to
1s — otherwise it breaks that memo.
