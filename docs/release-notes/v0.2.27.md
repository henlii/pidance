# v0.2.27

## 中文

### 队列重复发送

同一段队列消息可能被投递两次（实测：同一文本间隔 74 分钟两次落盘，两次都紧跟
在 agent 结束之后，都是 host 的队列 flush 发出的）。收口两条路径：

- **投递受理即出队**：消息被受理（prompt preflight 通过）时立即从队列移除并持久化，
  不再只等「用户消息落盘」或「本轮完成」确认。确认事件缺失（flush 被客户端整组
  替换中止、结束原因为中止/失败）时，已送达的消息不会留在队列里等下一次重发。
- **拒收过期回显**：host 队列快照带单调 revision（state 投影与 `sessionQueue.<id>`
  持久化一起下发，兼容旧的纯数组格式），客户端只接受不旧于已见版本的快照。
  此前旧快照会把已发送的队列写回界面与账本，下一次入队又把旧条目带回服务端。

### 运行中附带图片

agent 运行中粘贴/拖入图片此前被直接丢弃（无任何提示），也无法随引导/跟进发送。
现在：运行中可正常附带图片，引导（Ctrl+Enter）即时注入，跟进（Enter）走
follow-up 投递；二者都支持图片，被拒时把内容退回输入框并提示，不再静默丢失。

### 会话区布局统一

消息列、输入栏、扩展面板、扩展 widget、todo、底栏此前宽度不一（消息列 760、
输入区 820）。现在共用同一常量（`1230`，即原输入区宽度的 1.5 倍）与同一内边距，
两侧 18px 竖条作为对称边距，短会话也逐像素对齐。

- 右侧消息概览条 36px → 18px，并恢复其悬浮预览。
- 扩展自定义面板（扩展自行渲染的 TUI 面板）宽度与输入栏一致。
- 扩展 widget 内容加统一限高（与思考块、工具输出同口径），超长内容在块内滚动，
  不再把输入区顶出可视区（实测 80 行 widget 修复前会把输入框顶到屏幕外）。

### 新增：左侧用户消息导航条

- 每条用户消息一条短横线，列表整体上下居中，当前所在的一条为深色；
- 鼠标悬浮显示信息卡（最大 340×180，超出省略），点击跳到该消息顶部；
- 与右侧概览条分工：右侧总览整轮对话并可拖拽滚动，左侧只列提问。

### 扩展面板（询问/选择面板）

- 与输入框同宽同中心线（此前 560 宽、中线右偏 18px）；
- 打开时独占输入区：输入栏、消息队列、模型选择、底栏一并让位；
- 内容区限高内滚（此前超长内容被裁切），保留自动换行。

### 流式块显示

- 思考块与工具块不再随流式自动展开、也不自动收回：初始折叠，折叠/展开只由用户决定；
- 折叠态滚动显示最后一行输出（思考块与工具块各有一行预览）。

## English

### Duplicate queue delivery

A queued message could be delivered twice (observed: the same text landed twice,
74 minutes apart, both right after an agent settle and both from the host's
follow-up flush). Two paths are now closed:

- A queued item leaves the queue as soon as its prompt is accepted (and is
  persisted immediately), instead of waiting for the user-message/settle
  confirmation — a missing confirmation no longer leaves a delivered item
  waiting to be sent again.
- Queue snapshots carry a monotonic revision (state projection and persisted
  prefs, backward compatible with the old plain array); the client ignores
  snapshots older than the last one it saw, so a stale echo can no longer
  resurrect an already sent item.

### Images while the agent is running

Pasting or dropping an image while a run was active was silently dropped. Images
can now be attached during a run: steer (Ctrl+Enter) injects them immediately,
follow-up (Enter) delivers them through the follow-up path. If delivery is
rejected, the content is returned to the input with a notice.

### Unified chat column layout

Message column, input bar, extension panel, widgets, todo panel and footer now
share one width constant (`1230`, i.e. 1.5× the previous input width) and the
same padding; 18px rails on both sides provide symmetric gutters.

- Right minimap: 36px → 18px, with its hover preview restored.
- Custom extension panel width now matches the input bar.
- Extension widget content is height-capped (same cap as thinking/tool blocks)
  and scrolls internally instead of pushing the input off screen.

### New: left user-message navigation rail

One short dash per user message, vertically centred, with the current one
emphasised; hovering shows an info card (max 340×180, ellipsised) and clicking
jumps to that message.

### Extension panel

- Same width and centre line as the input bar;
- While open it takes over the composer: input bar, queue, model selector and
  footer step aside;
- Content is height-capped and scrolls internally (wrapping preserved).

### Streaming blocks

- Thinking and tool blocks no longer auto-expand or auto-collapse; the initial
  state is collapsed and toggling is user-driven only;
- While collapsed they scroll the last output line.
