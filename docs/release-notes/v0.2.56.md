# v0.2.56

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、自动重试：横幅不再闪没，停止按钮与执行时间都留着

网络抖动触发自动重试时，界面会先把这一轮当成结束：重试提示一闪就没、停止按钮消失、会话列表的
执行时间归零。根因是 `agent_end` 带着 `willRetry: true` 只是**重试的中间点**，一轮真正的结束是
`agent_settled`，或那次不带 `willRetry` 的 `agent_end`；我们却把中间点当终局，清了运行态与计时、
发了 `prompt_done`，客户端跟着收尾。

现在重试期间不清运行态与计时、不收尾（`steer` 依旧连续计时，排队的消息开始执行时重新计时）。
退避期间被中止那条路径只发 `auto_retry_end` + `agent_settled`、不再发第二个 `agent_end`，
所以也把计时清理与异常红点补在 `agent_settled` 上。重连的标签页同样能恢复横幅与停止按钮
（快照缓存重试状态，并在重试挂起时如实报告「在跑」）。

### 二、未读与「等待你回复」两处信号

- **选中的会话跑完仍被标未读，切到别的会话才看到点**。两个真因：一是推 `readAt` 之前没等服务端
  偏好到齐，而本地那份只是首屏缓存，服务端对 `unreadSessionState` 的子键又是**整份替换**，
  旧缓存 PUT 一次就把整张 `readAt` 表盖回去；二是客户端错过 running→idle 那次跃迁时（流断过、
  页面在刷新、被别的端盖过）没有任何东西把 `readAt` 补上。现在推之前先等服务端偏好，且当前
  选中的会话在时钟里仍是未读时会补一次已读（取 `max(now, completedAt)`，本端时钟偏慢也补得动）。
- **扩展面板阻塞会话时不显示黄点**。侧栏「等待你回复」过去只统计扩展的 pending 对话框，而插件
  自绘面板没有可重放的请求对象 —— 0.2.55 把 `select`/`confirm` 也交给面板渲染之后，这条信号就
  整条断了。现在面板也算「等你操作」。

### 三、登录后不再需要手动刷新

首次未登录访问时，根组件的偏好请求与全局事件流都会吃 401 并被缓存成空态；登录成功后如果不刷新
页面，项目列表、未读状态、主题与跨端广播就一直空着。现在登录成功会重连事件流、同步一次服务端
偏好，再整页刷新。顺带修掉「偏好加载失败时写入会自旋」——离线或未登录下会无限重试，把测试进程
挂死。

### 四、其它细节

bash 块展开后命令会显示两遍（工具自己画的调用行 + 我们额外的「命令」分区），现在只画一遍；
用户自己跑的 `!命令` 不受影响。未读时钟写盘不再漏到默认目录（host 会带上自己的 agent 目录）。

### 五、仓库整理

按知识分层重排了文档：决策进 Agent Note，事故复盘与历史设计稿移出公开仓（移到本机 `debug/`），
根 `AGENTS.md` 压到约 180 词。**公开仓因此删掉了 32 个历史文档**（12 份消息发送评审与复现脚本、
`ui-redesign/`、扩展 UI 计划与缺口清单、跳转 handoff、渲染 livelock 复盘、架构评审、SDK 升级
计划等）；这些记录现在只在本机，不再随仓库分发。代码与测试没受影响。

桌面壳本轮仍不发（用户决定暂时停更），因此不改 `desktop/` 的版本与 lockfile。

### 验收范围

`tsc --noEmit`；eslint 0 error；`npm test` 2888 项。31416 实测：扩展面板打开时侧栏显示
「等待你回复」、面板与服务端两边一致，取消后消失；注入「completedAt 比 readAt 晚」的坏状态后
本地与服务端的 `readAt` 都被补齐、切到别的会话不再显示未读点；bash 块展开后命令计数 3 → 2
（工具调用行 + 合法输出）。自动重试的时序由假 provider（首个请求回 HTTP 500）的 host 集成测试
覆盖：中间 `agent_end` 不得清计时/写异常红点、整轮只发一次 `prompt_done`、退避期间中止要收干净。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Auto-retry: the banner no longer flashes away, and the stop button and timer stay

When a network hiccup triggers an automatic retry, the UI used to treat that round as finished: the
retry notice flashed and vanished, the stop button disappeared and the sidebar run timer reset. The
cause is that `agent_end` with `willRetry: true` is only the **midpoint** of a retry — a run really
ends at `agent_settled`, or at the `agent_end` that does not carry `willRetry` — but we treated the
midpoint as terminal and tore down run state and timing. Retries now keep run state and timing alive;
steering keeps timing continuous and a queued message restarts it. Aborting during the backoff emits
only `auto_retry_end` + `agent_settled` (no second `agent_end`), so timing cleanup and the abnormal
marker now also run there. A reconnecting tab restores the banner and stop button too.

### 2. Two session signals: unread and "waiting for you"

- **A selected session stayed unread after its run finished** until you switched away. Two causes:
  `readAt` was pushed before the server preferences had loaded (the local copy is only a first-paint
  cache, and the server replaces the whole `readAt` map per sub-key), and nothing advanced `readAt`
  when the client missed the running→idle transition. It now waits for the server preferences and
  bumps the selected session to read in the clock itself.
- **The yellow dot disappeared when a plugin panel blocked a session**: the sidebar counted only
  pending dialogs, and plugin-drawn panels have no replayable request object — so when 0.2.55 moved
  `select`/`confirm` onto the panel path, the signal broke. Panels now count as waiting.

### 3. No manual refresh after signing in

An unauthenticated first visit makes the root-level preference request and the global event stream
fail with 401 and cache empty state, so signing in without a page reload left projects, unread state,
theme and cross-client broadcasts empty. Signing in now reconnects the stream, syncs server
preferences once and reloads. The "preference write spins forever when loading fails" bug (which
could hang a test process offline) is fixed as well.

### 4. Other details

The bash command was drawn twice when the block was expanded; it is now drawn once (and the user's own
`!command` output is unaffected). The unread clock no longer leaks into the default agent directory.

### 5. Repository tidy-up

Documentation was reorganised by tier: decisions moved into Agent Notes, postmortems and historical
design drafts moved out of the public repository (into a local `debug/`), and the root `AGENTS.md`
shrank to about 180 words. **The public repository therefore dropped 32 historical documents** (12
message-send reviews and repro scripts, `ui-redesign/`, the extension-UI plan and gap list, the
message-jump handoff, the render livelock postmortem, an architecture review, the SDK upgrade plan).
Those records now live only on this machine. Code and tests are unaffected.

The desktop shell is not released this time (frozen by user decision).

### Verification

`tsc --noEmit`; eslint 0 errors; `npm test` 2888 tests. Measured on 31416: opening an extension panel
shows "waiting for you" in the sidebar and on the server, disappearing on cancel; injecting a state
where `completedAt` is newer than `readAt` gets repaired on both the client and the server, and
switching away no longer shows an unread dot; the bash command count dropped from 3 to 2 when the
block is expanded. Retry timing is covered by a host integration test with a fake provider that
answers HTTP 500 to the first request.
