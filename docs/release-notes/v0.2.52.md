# v0.2.52

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 修掉一处持续空转的渲染（手机发热/耗电的直接来源）

`AppShellInner` 在空闲时也在每秒重渲染 **278 次**，而 DOM 每秒只变化 2 次
（用 MutationObserver 实测）—— 纯烧 CPU。

根因是一个闭环：`ChatWindow` 每帧调用 `onBranchDataChange`，而该回调每次都把
**新引用**的分支树数组写进 `AppShellInner` 的 state，React 无法 bail-out，于是
「渲染 → effect → setState → 渲染」不停循环。

现在按内容签名判等（分支 leaf + 树长度 + 各节点 `entry.id` + actions 键集），
结构没变就不写状态。实测：**278 次/秒 → 0**。

### 思考档位：host 启动时按磁盘权威值收敛

SDK 建 session 时 `leafId` 尚未恢复，`getBranch()` 取不到分支，于是档位直接落到
`settings.json` 的 `defaultThinkingLevel` —— **会话自己的档位从没被读过**。表现为
「改成 high 没反应（SDK 认为没变化、不写盘）」「改成 max 后一刷新又变回去」。

现在 host 启动后会按磁盘（会话文件里最后一条 entry 所在分支）的权威档位收敛一次，
不再依赖 SDK 的分支索引。

### 侧栏两处修正

- **下拉只弹一次**：「显示选项」等菜单的入场动画初值取了 `open`，导致挂载那一帧先
  可见、随即被设回不可见、两帧后再显示 —— 视觉上「弹两次」。该组件的 3 处使用一并修正。
- **取消勾选「最近会话」= 整区隐藏**：此前只藏会话行，标题行无条件渲染，看起来像
  「收起」。现在标题行与会话行一起消失，要恢复就回「显示选项」重新勾上。

### 验收范围

`tsc --noEmit`；`npm test` 2775 项；31416 实测：`AppShellInner` 渲染 278 次/秒 → 0；
思考档位设 high/max 均能写盘并读回、禁用档位仍被正确钳制。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### A constant idle re-render removed (the main source of phone heat/battery drain)

`AppShellInner` re-rendered **278 times per second** while idle, while the DOM only changed
twice per second (measured with a MutationObserver) — pure CPU burn.

The cause was a loop: `ChatWindow` called `onBranchDataChange` on every frame, and that
callback wrote a **freshly-referenced** branch-tree array into `AppShellInner` state every time,
so React could never bail out and the cycle "render → effect → setState → render" never stopped.

It now compares a content signature (branch leaf + tree length + each node's `entry.id` +
action key set) and skips the state write when nothing structural changed. Measured:
**278/s → 0**.

### Thinking level: align with the disk on host startup

When the SDK creates a session, `leafId` has not been restored yet, so `getBranch()` returns
nothing and the level falls back to `settings.json`'s `defaultThinkingLevel` — **the session's
own level was never read**. Symptoms: setting `high` appeared to do nothing (the SDK saw no
change and did not persist), and setting `max` reverted on the next refresh.

The host now converges once at startup using the authoritative level from disk (the branch
ending at the session file's last entry), without relying on the SDK's branch index.

### Two sidebar fixes

- **Dropdowns open once**: the enter animation initialised its visibility from `open`, so the
  panel was visible for the mount frame, then hidden, then shown again two frames later — read
  as "opening twice". All three users of that component are fixed.
- **Unchecking "Recent sessions" hides the whole zone**: previously only the session rows were
  hidden while the header rendered unconditionally, which looked like "collapsed". Now the
  header goes with it; re-check the option to bring it back.
