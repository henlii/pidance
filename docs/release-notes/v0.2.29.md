## 中文

### 切换模型失败可诊断：无原因 4xx 不再无声卡死

现象：旧会话聊天几轮后切到另一个模型，会「一直报错无法继续」。核实后切换动作本身没问题
（`set_model` 成功、`model_change` 已落盘），坏的是切换后的第一个请求：

- 上游拒绝请求但**不返回原因**（无 body 的 400），而 SDK 的上下文溢出识别用的是带 `^`
  锚定的文本正则，拿不到该签名，于是既不压缩也不重试，同一个超限请求被反复重发，会话对该
  模型死锁。实测 `cpa/grok-4.6` 声明窗口 500000，而 ≈381K 的会话已被上游拒。
- 单变量复现（重放抓到的原始请求体）：只改 `max_output_tokens`（114044 → 16384 → 4096）、
  只改 `reasoning.effort`（xhigh/low/删除）、只去掉跨模型可能残留的字段，全部仍是 400；
  只有**减少输入量**（删掉最老的 25% / 40%）才返回 200 —— 输入体积是唯一变量。

本版只做可诊断与人工出口，**不自动压缩、不自动重发用户输入**：

- `lib/provider-error.ts`：纯函数分类「上游拒绝但未给原因」，只认无 body 的
  400/413/422；401/403/404/429（凭证/路由/限流）语义明确，一律不归入。
- 错误卡片：命中时给出疑似容量提示 + 本会话占用（标注为估算）+ **「压缩上下文」按钮**
  （复用既有压缩入口），压缩完成后提示重新发送上一条消息。
- 模型选择器：每行显示「本会话 ≈X tokens（估算）／该模型声明窗口 Y」，占用超过
  声明窗口 − 预留（16384，与 SDK 默认一致）时加警示标记。声明值可能高于上游真实限额，
  命中只提示、不阻止切换。
- 占用优先取热 state，非 live（打开历史/只读）会话回退磁盘统计，避免读数缺失。

### 跳转到历史：按「点击 → 加载 → 锚回加载前内容 → 滚到目标」的顺序

用户给出的期望顺序是四步，本版把它逐条做实，并顺手消灭三处抢跑：

- **换窗不再闪一帧错误位置**：服务端定位会整体替换时间线，内容高度随之变化，而
  `scrollToTarget` 的首次定位原本要等两帧稳定才平滑滚动 —— 那一帧先按旧 `scrollTop`
  绘制，看起来就是「内容被换掉再滚过去」。现在走定位的路径直接在 `waitForTarget` 的 rAF
  微任务里（绘制前）贴顶，再进入既有有界收敛。
- **加载完成的同时锚回加载前那段内容**：`captureAnchor` 在替换时间线**之前**记下视口顶
  那条消息及其相对容器顶的偏移，`applyAnchorOffset` 在定位返回后同一 rAF 内还原。新窗口
  是分批挂载的，一次性还原只挡住第一帧（实测之后仍漂 1695px），因此填充期每帧重钉
  （`holdAnchor`）。锚点还原发生在滚动动画之前，所以动画仍从「用户原本看的位置」出发；
  旧内容不在新窗口时退化为就地贴到目标（不闪、无动画）。
- **不再「先向下滚一段再替换」**：真正抢跑的是自动跟随 —— 切「浏览历史」态写在 hydrate
  之后，hydrate 提交新窗口那一帧高度变化，此时仍处于 following，于是先钉底再切态。
  现在 `notifyBrowsingHistory()` 提到请求之前，整段定位过程都不被钉底打断；仓库已有的
  顺序门禁里加了一条断言固定这个先后关系。
- **不再「先跳过去又退回」**：跳转要经过「替换时间线 → 等渲染 → 滚动到位」几拍，期间
  scroll 事件会按旧视口解析出旧当前项，把高亮改回去（此前只修了收尾用旧闭包，没修中途被
  旧视口覆盖）。新增跳转期钉住 + 5s 看门狗（滚动链异常终止时兜底解除，避免导航条永久
  不再跟随）。
- 滚动动画改为自控：`easeInOutCubic` + 420ms（原生 smooth 时长不可调，观感偏快）。

验证（31416 + agent-browser，帧级记录 `scrollTop`/锚点偏移）：换窗帧 `scrollTop` 未变、
锚点在 52975px 外（旧代码在此闪一帧）→ 下一帧按锚点还原、锚点回到加载前偏移 → 随后
19 帧连续变化 → 落点 `topRel = 0`。

### 导航条本身：跟随居中、上下指示器、平滑与减少动画

- 跟随当前项并把它滚到轨道中部（新增 `centeredRailScrollTop`，内容未溢出恒 0），
  当前项的横线长度是其它项的 2 倍，长会话里随时能看出「当前在哪」。
- 轨道上方/下方各加一个 8×5 的小三角，仅在对应方向确实还能滚动时显示（含 1px 容差，
  小数滚动位置下贴边不闪），装饰性元素 `aria-hidden`、不抢横线的点击。
- 跟随时位移小于 24px 用瞬时定位（避免每帧重启动画而发飘），真正的跳转才动画；
  `prefers-reduced-motion` 下全部瞬时。24px 与 420ms 都是初值，观感需人工确认。

### 打开旧会话首次向上滚动不再跳一大段

补偿本身数学上是对的，问题在时机与条件：补偿写在 `useEffect`（**绘制之后**才跑），
prepend 先把视口下推、用户先看到位移再被拉回；而今改为 `useLayoutEffect`（绘制前同步补偿），
并新增 `shouldCompensatePrepend` —— 只有「有待补偿快照」且「头部 entry id 变老」（真的
prepend）才补偿，尾部追加（流式/新消息）不再被误补。距离快照随会话切换清空，
`loadOlderHistory` 返回 false 时作废，不再留到下一个无关变化才生效。

### 思考块与工具块：整行可点，历史思考块能读到正文

- 工具块/思考块此前只有标签那一小段能点开，现改为整行可点击。
- 历史思考块的正文在服务端是 deferred（`thinking: ""`），此前折叠行留空**不是展示规则**
  而是正文没加载 —— 看起来像内容丢失。现在折叠行统一取末行，并新增
  `IntersectionObserver`（`rootMargin: 100%`）提前一屏触发既有的 `loadIfDeferred()`，
  不改变「展开才加载」之外的语义，长会话仍不会一次性拉取所有历史思考块。
- `BlockHeaderRow` 新增 `showCommandLabel`：把「命令」小字从缩进解耦，思考块分区表头不再
  误显示工具标签。

### 运行租约：失权停写、不驱逐活持有者、启动回收

- 活持有者的写权不再被 TTL 抢占（心跳与清理路径同样不得驱逐活持有者），失权即停写。
- 启动时回收失效运行租约文件：回收逻辑一直在，但两个导出没有任何生产调用方，于是目录
  无界增长 —— 实测 2615 个文件 / 11MB 且按天累积，抽样 300 个全属已死进程（全目录扫描
  171ms，在用仅 2 个）。现在启动扫一次，只删持有者已死或内容损坏的；心跳过期但进程仍活
  的一律保留。31416 实测启动日志「已回收 2614 个失效运行租约文件（在用的 1 个）」，
  目录 11MB → 208K。
- host 销毁生命周期契约补齐（等待语义、多订阅、writer busy 时 fail closed）。

### 会话投影归属与队列写入

- 为 A 发起的 reconcile 在切到 B 之后返回，A 的压缩态与吞吐读数会被写进 B 的界面。
  判定抽为 `lib/session-projection.ts` 的 `canApplyProjection(target, view)`（会话归属 +
  读数代次），并在三处调用点接线；`loadSession` 的 agentState 分支所有直写字段同样加守卫。
- 队列格式统一解码器 + 多标签条件写入（CAS），旧快照不再把已发送的条目写回界面与账本。

### 新建会话提交事务、空闲 slot 有界回收

- 新建会话改为提交事务 + 显式取消，不再依赖本地 fetch 取消。
- `dispose()` 只退订视图、不删 slot，于是一个页面里打开过的每个会话都会一直留着完整
  timeline 与派生数组直到刷新。现在在既有空闲窗口到期时有界回收，条件保守到「宁可多留
  一个 slot，不可丢掉用户消息」：无视图、无订阅者、未运行、无在途提交、无待结算 abort、
  timeline 中无 pending 记录且无未绑定的 submissionKey、timeline 非空。

### 四个小口子

- **SDK 私有落盘入口收敛**：`pi-session-io` 直接摸 SDK 私有 `_rewriteFile` / `flushed`
  且用 optional call —— SDK 升级后成员改名会**静默不落盘**（新会话列表看不到、无法删除）。
  核实公开替代确实不存在后，收敛为 `SdkFileSurface` 适配层，缺失即抛
  `SDK_SESSION_FILE_SURFACE_MISSING`，并在 sdk-import-allowlist 加升级门禁（d.ts 里不再
  有这两个成员就失败）。
- **扩展 custom 面板**：只有 SSE 事件、没有重放，切走/刷新后服务端仍在等输入而浏览器端
  既无内容也无入口。新增可重放快照（`get_state.activeCustomUi` + `restoreCustomUi`）。
- **`POST /api/agent/new` 输入错误返回 400**：Route 用 `String(error)` 与原文比较，而
  `String(new Error("cwd is required"))` 带 `Error:` 前缀，两个 400 分支永不命中，缺参数与
  目录不存在都被报成 500（31416 实测已修正）。
- **`npm run dev` 改用工作区端口**：脚本曾硬编码 31415（保留给稳定安装版），文档只写
  「不要这样用」。现在为 `next dev --turbopack -H 127.0.0.1 -p 31416` 并加静态门禁固定
  契约；dev 无密码，显式只绑回环。

## English

Package: `@henlii/pidance` · CLI: `pidance` · `npm run check` before release: clean typecheck,
0 lint errors, 1451 tests passing.

### A failed model switch is now diagnosable instead of silently stuck

Symptom: after a few turns in an existing session, switching to another model kept failing with
no way to continue. The switch itself was fine (`set_model` succeeded, `model_change` was
persisted) — the first request after it was not:

- The upstream rejects the request **without a reason** (400 with no body), while the SDK detects
  context overflow with an `^`-anchored text regex, so it neither compacts nor retries and the same
  oversized request is resent forever, deadlocking the session on that model. In practice
  `cpa/grok-4.6` declares a 500000 window while a ≈381K session was already rejected.
- Single-variable replay of the captured request body: changing only `max_output_tokens`
  (114044 → 16384 → 4096), only `reasoning.effort` (xhigh/low/removed), or dropping fields that
  could leak across models all still returned 400; only **reducing the input** (dropping the
  oldest 25% / 40%) returned 200 — input volume is the only variable.

This release only adds diagnostics and a manual way out — **no automatic compaction, no automatic
resend of user input**:

- `lib/provider-error.ts` classifies "upstream rejected without a reason": only bodyless
  400/413/422; 401/403/404/429 (credentials/routing/rate limit) are never included.
- The error card shows a suspected-capacity hint plus this session's usage (marked as an estimate)
  and a **"Compact context"** button (reusing the existing manual compaction), then tells the user
  to resend the last message.
- The model picker shows "this session ≈X tokens (estimated) / declared window Y" per row and
  flags rows where usage exceeds the declared window minus the reserve (16384, matching the SDK
  default). Declared values can exceed real upstream limits, so a flag only warns, never blocks.
- Usage prefers live state and falls back to disk statistics for non-live sessions (opened from
  history or read-only), so the reading is never missing.

### Jumping into history follows "click → load → anchor back → scroll to target"

The order the user specified is implemented step by step, together with three fixes for effects
that raced ahead:

- **No more frame of the wrong position**: server-side location replaces the whole timeline and
  changes its height, while `scrollToTarget` used to wait two stable frames before scrolling
  smoothly — that frame painted the old `scrollTop`, which looked like "content swapped, then it
  scrolled". The locating path now pins the target inside `waitForTarget`'s rAF microtask (before
  paint) and then enters the existing bounded correction.
- **The visible part before loading is anchored back**: `captureAnchor` records the topmost
  message and its offset relative to the container *before* the timeline is replaced, and
  `applyAnchorOffset` restores it in the same rAF that receives the response. The new window mounts
  in batches, so a one-shot restore only held the first frame (measured: it still drifted 1695px),
  hence re-pinning every frame while filling (`holdAnchor`). The restore happens *before* the
  scroll animation, so the animation still starts from where the user was looking; if the old
  content is not in the new window it degrades to pinning the target without animation.
- **No more "scroll down, then replace"**: the real early actor was auto-follow — switching to the
  "browsing history" mode happened after hydrate, so the frame that committed the new window still
  pinned to the bottom first. `notifyBrowsingHistory()` now runs before the request, so the whole
  locate/commit/scroll sequence is uninterrupted, and the existing ordering gate gained an
  assertion to lock that order in.
- **No more "jump then bounce back"**: the jump takes several beats, and scroll events resolved the
  previous active entry against the old viewport, moving the highlight back. Jump-scoped pinning was
  added with a 5s watchdog as a bound (a stuck scroll chain would otherwise stop the rail from
  following forever).
- Scrolling animation is now self-driven: `easeInOutCubic` + 420ms (native smooth duration is not
  configurable and felt too fast).

Verified on 31416 with agent-browser, recording `scrollTop`/anchor offset per frame: the swap frame
keeps `scrollTop` with the anchor 52975px away (the old code flashed a frame here) → the next frame
restores the anchor to its pre-load offset → 19 consecutive animation frames → landing at
`topRel = 0`.

### The rail itself: centred following, scroll hints, smoothness with reduced motion

- The active entry is centred in the rail (new `centeredRailScrollTop`, always 0 when the content
  does not overflow) and its dash is twice as long as the others.
- An 8×5 triangle above and below appears only when that direction can still scroll (1px tolerance
  so fractional scroll positions do not flicker); the decorations are `aria-hidden` and never
  steal the dash clicks.
- Following uses instant positioning for displacements under 24px (restarting an animation every
  frame felt floaty); only real jumps animate. Everything is instant under
  `prefers-reduced-motion`. Both 24px and 420ms are initial values and need a human look.

### Opening an old session no longer jumps when scrolling up for the first time

The compensation maths were right; the timing and conditions were not: it ran in `useEffect`
(**after** paint), so the prepend pushed the viewport down visibly before being pulled back. It now
runs in `useLayoutEffect` (synchronously before paint) and a new `shouldCompensatePrepend` only
compensates when there is a pending snapshot *and* the head entry id grew older (a real prepend),
so tail appends (streaming/new messages) are no longer compensated by mistake. The distance
snapshot is cleared on session switch and invalidated when `loadOlderHistory` returns false.

### Thinking and tool blocks: clickable as a whole row, historical thinking readable

- Tool/thinking blocks used to be clickable only on the small label; the whole row toggles now.
- Historical thinking bodies are deferred server-side (`thinking: ""`), so the empty collapsed row
  was not a display rule but unloaded content — it looked like data loss. Collapsed rows now show
  the last line, and an `IntersectionObserver` (`rootMargin: 100%`) triggers the existing
  `loadIfDeferred()` one screen ahead, so long sessions still do not fetch every historical block
  at once.
- `BlockHeaderRow` gained `showCommandLabel`, decoupling the small "command" label from indentation
  so thinking section headers no longer show tool labels.

### Run leases: stop writing when losing the lease, never evict a live holder, sweep at startup

- A live holder's write right is no longer preempted by TTL (heartbeat and cleanup paths alike must
  not evict a live holder), and losing the lease stops writes.
- Stale lease files are swept at startup: the collection logic existed, but both exports had no
  production caller, so the directory grew without bound — measured 2615 files / 11MB and growing
  daily, with 300 sampled files all owned by dead processes (a full scan took 171ms; only 2 were
  live). It now sweeps once at startup and deletes only entries whose owner is dead or whose
  content is corrupt; leases with an expired heartbeat but a live process are always kept. On
  31416 the startup log read "reclaimed 2614 stale run lease files (1 in use)" and the directory
  went from 11MB to 208K.
- The host dispose lifecycle contract is complete (wait semantics, multiple subscribers, fail
  closed when the writer is busy).

### Session projection ownership and queue writes

- A reconcile started for A and returning after switching to B used to write A's compaction state
  and throughput reading into B's UI. The rule is extracted as `canApplyProjection(target, view)`
  in `lib/session-projection.ts` (session ownership + reading generation) and wired at three call
  sites; every direct write in `loadSession`'s agentState branch is guarded too.
- One decoder for queue formats plus conditional (CAS) writes with multiple tabs, so stale
  snapshots no longer write already-sent items back into the UI and the ledger.

### New-session commit transaction, bounded idle slot collection

- Creating a session is now a commit transaction with explicit cancellation instead of relying on
  local fetch cancellation.
- `dispose()` only unsubscribed the view and never deleted the slot, so every session opened in a
  page kept its full timeline and derived arrays until reload. Idle slots are now collected when
  the existing idle window expires, with deliberately conservative conditions ("keep one slot too
  many rather than lose a user message"): no view, no subscribers, not running, no in-flight
  commit, no unsettled abort, no pending records or unbound submission key in the timeline, and a
  non-empty timeline.

### Four smaller holes

- **SDK private persistence entry points**: `pi-session-io` touched the private
  `_rewriteFile` / `flushed` through optional calls — a renamed member after an SDK upgrade would
  **silently skip persistence** (a new session invisible in the list and undeletable). After
  confirming no public alternative exists, it is funnelled through an `SdkFileSurface` adapter that
  throws `SDK_SESSION_FILE_SURFACE_MISSING` when missing, with an upgrade gate in the
  sdk-import-allowlist (fail if the d.ts no longer has those members).
- **Extension custom panels**: they had SSE events but no replay, so after switching away or
  reloading the server was still waiting for input while the browser had neither content nor an
  entry point. A replayable snapshot was added (`get_state.activeCustomUi` + `restoreCustomUi`).
- **`POST /api/agent/new` returns 400 for input errors**: the route compared `String(error)`
  against raw text while `String(new Error("cwd is required"))` has an `Error:` prefix, so neither
  400 branch ever matched and a missing argument or nonexistent directory reported 500 (verified
  fixed on 31416).
- **`npm run dev` uses the workspace port**: the script hard-coded 31415 (reserved for the stable
  install) while the docs only said "do not do that". It is now
  `next dev --turbopack -H 127.0.0.1 -p 31416` with a static gate locking the contract; dev has no
  password, so it binds loopback explicitly.
