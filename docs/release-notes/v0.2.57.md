# v0.2.57

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、内核升到 1.2.0，修掉「新装版本会话全打不开」

0.2.56 全新安装后会出现**会话列表加载失败（HTTP 500）**，整站 API 都在进入路由前就抛
`SyntaxError: The requested module '@earendil-works/pi-codemode/declarations' does not provide an export named 'MCP_TYPESCRIPT_PREAMBLE'`。

根因不在 Pidance 自己的代码：0.2.56 精确锁定了 `pi-coding-agent@1.1.0`，而该版本内部仍然
`import { MCP_TYPESCRIPT_PREAMBLE }`，它对 `pi-codemode` 的依赖写的是 `^1.1.0`；`pi-codemode@1.2.0`
（2026-10-12 发布）删掉了这个导出。于是安装时 npm 按 caret 解析到 1.2.0，导入期即语法错误，
路由里的 try/catch 根本没执行，所有 API 一律 500。

现在 `pi-coding-agent` 与 `pi-tui` 一起精确升到 **1.2.0**，`pi-codemode` / `pi-ai` / `pi-mcp` /
`pi-agent-core` / `pi-telemetry` 同为 1.2.0，整族版本一致。1.2.0 的破坏性变更逐条核对后本仓无一命中
（`before_agent_start` 的 `messageType` 联合类型、启动期 busy 语义与 `deliverAs`、`pi mcp list --json`
的字段变化、`serializeConversation()` 省略 thinking、`reachesTools` / `aliases`）。

### 二、models.json 保存不再写没根级 `$schema`

1.2.0 起 Pi 的配置文件支持根级 `"$schema"`（编辑器补全与校验）。而设置页保存 models.json 时只写回
`{ providers }`，根级键整份丢弃 —— 面板的 GET 投影本来就只回 providers，载荷里根本带不回
`$schema`，所以一保存就没了。现在**以磁盘现值为底**、载荷给出的根级键覆盖其上，`providers` 仍用
合并结果，用户手工加上的 `$schema` 不再消失。

### 三、settings.json 的 skills 支持 `~`

Pi 按 `resolvePath` 展开路径开头的 `~`，而技能发现过去直接 `resolve(cwd, ...)`：`"skills":
["~/skills/xxx"]` 在 Pi 侧能加载，在「技能」页却报「路径不存在」。现在与 Pi 对齐（复用仓内既有的
`expandTilde`，并支持注入 home 以便测试）。

### 四、内置主题的 `$schema` 指向

两个内置主题（dark / light）的 `$schema` 原本指向上游源码里的旧地址，该地址已 404；改为 1.2.0
文档给出的新地址 `https://pi.dev/schemas/theme.schema.json`（实测 200）。

### 验收范围

`tsc --noEmit`；eslint 0 error（196 warning，与 0.2.56 同量）；`npm test` 2890 项（新增「根级
`$schema` 保存保留」与「`skills` 的 `~` 展开」两条）。31416 部署冒烟通过；正式制品走隔离根
webpack 构建 + 生成前/后审计 + tgz 安装冒烟。

桌面壳本轮仍不发（用户决定暂时停更），因此不改 `desktop/` 的版本与 lockfile。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Kernel moved to 1.2.0, fixing "sessions won't open on a fresh install"

A fresh install of 0.2.56 failed with **"Failed to load the session list" (HTTP 500)**: every API
route threw before reaching its handler —
`SyntaxError: The requested module '@earendil-works/pi-codemode/declarations' does not provide an export named 'MCP_TYPESCRIPT_PREAMBLE'`.

The cause was not Pidance's own code: 0.2.56 pinned `pi-coding-agent@1.1.0`, which still
`import`s `MCP_TYPESCRIPT_PREAMBLE` while declaring its own dependency as `^1.1.0`, and
`pi-codemode@1.2.0` (published 2026-10-12) removed that export. npm therefore resolved 1.2.0 on
install, the import failed at module load, and every API answered 500 — the `try`/`catch` inside the
routes never even ran.

`pi-coding-agent` and `pi-tui` now both pin **1.2.0**, with `pi-codemode` / `pi-ai` / `pi-mcp` /
`pi-agent-core` / `pi-telemetry` at 1.2.0 as well, so the whole family matches. Every breaking change
in 1.2.0 was checked against this repository and none applies (the `messageType` union on
`before_agent_start`, the busy-at-run-start semantics and `deliverAs`, the `pi mcp list --json` field
change, `serializeConversation()` dropping thinking blocks, `reachesTools` / `aliases`).

### 2. Saving models.json no longer drops a root-level `$schema`

Since 1.2.0 Pi's configuration files accept a root-level `"$schema"` for editor completion and
validation. Saving models.json from the settings page wrote back only `{ providers }`, discarding
root-level keys — and because the panel's GET projection returns providers only, the payload could
never carry `$schema` back. Saving now starts from the on-disk value and lets root-level keys from the
payload override it, while `providers` still uses the merged result, so a hand-added `$schema`
survives.

### 3. `~` in settings.json `skills`

Pi expands a leading `~` through `resolvePath`, while skill discovery called `resolve(cwd, ...)`
directly: `"skills": ["~/skills/xxx"]` loaded fine under Pi but reported "path does not exist" on the
Skills page. Discovery now matches Pi (reusing the existing `expandTilde`, with an injectable home for
tests).

### 4. `$schema` of the built-in themes

Both built-in themes (dark / light) pointed their `$schema` at an upstream source path that now
returns 404; they now use the address from the 1.2.0 docs,
`https://pi.dev/schemas/theme.schema.json` (verified 200).

### Verification

`tsc --noEmit`; eslint 0 errors (196 warnings, the same count as 0.2.56); `npm test` 2890 tests
(two new ones: root-level `$schema` preserved on save, and `~` expansion for `skills`). 31416 deploy
smoke passed; the official artifact goes through an isolated webpack build with pre/post-pack audits
and a tgz install smoke.

The desktop shell is not released this time (frozen by user decision).
