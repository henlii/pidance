# v0.2.28

## 中文

### 导航条列出全部提问，按 entryId 精确定位

此前导航条只看已渲染的 DOM，长会话里只列得出几条（实测 10 条提问只出 2 条）——
会话是两层懒加载（分页加载 + 只渲染末尾 N 条）。现在：

- 新增 `GET /api/sessions/:id/outline`，按**当前 leaf 分支**抽取全部用户提问，
  与上下文窗口同口径（不会列出其它分支的提问，那些条定位不到）。
- 横线数量 = 提问数，不再受渲染窗口限制；短列表居中，长列表（>320px）内部滚动，
  首尾都点得到。
- 点击按 entryId 请服务端定位：窗口从锚点**一直取到最新**，跳转后时间线仍是
  「选中位置 → 最新」整段，运行中会话的尾部流式输出不脱离时间线。
- 「当前提问」高亮按几何位置推导（取真正最靠上的已渲染消息，而不是 DOM 顺序）。
- 定位到历史中段后，底部保留「加载较新的消息」，向下继续浏览的路径不丢。
- 跳转受 `{sessionId, leafId, jumpGeneration}` 门禁：切会话/切分支/连点两次后，
  旧响应不会改写时间线。

### 导航条外观与交互

- 横线相对轨道左侧内缩 4px；间距 9 → 4px；悬浮项变黑并加长（12 → 24px）。
- 轨道只有 18px 宽，悬浮加长会被裁并冒出横向滚动条 —— 改为两层结构（外层只做
  垂直居中与限高并保持 `overflow: visible`，内层才是纵向滚动容器）。
- 跳转从瞬时换屏改为平滑滚动：动画期间用户滚轮/触摸可自然接管。

### 跳转卡顿修复（主线程占用 97% → 0–2 个长任务）

长会话（1479 条消息）里按 entryId 跳到历史，会整体替换时间线，React 要同步渲染
整批「过程详情」子树 —— 一轮过程含 40–50 条消息、47 次工具调用，三个块就占 1.6 万
DOM 节点。实测（每次跳转前重新加载取干净样本）：

| 跳转位置 | 长任务累计 / 峰值 | 主线程占用 | DOM 节点 |
|---|---|---|---|
| 最早 | 5433ms（峰值 903ms） → 170ms（峰值 115ms） | 97% → 41% | 27187 → 2852 |
| 中间 | 5435ms（峰值 294ms） → 173ms（峰值 92ms） | 96% → 81% | 10744 → 3800 |

三条提问的落点均为 `topRel = 0`，与修复前一致 —— **没有拿精度换性能**。

- 「过程详情」展开态的内容改为**进视口才挂载、离开视口卸载**（提前 1.5 屏预挂载，
  避免滚动到空白）。卸载后用上次实测高度占位，挂载/卸载前后布局几乎不变。
  默认展开与折叠按钮行为不变；无 `IntersectionObserver` 的环境（SSR、老浏览器）
  退化为直接挂载。
- 滚动侧：元素列表按渲染批次缓存（不再每个 scroll 事件查 DOM），scroll 与
  `ResizeObserver` 经 rAF 合并成一帧最多一次测量。
- 落点收敛：等布局稳定再平滑滚动，动画停下后做有界校正（偏离 >2px 才校正，
  最多 12 次 × 100ms）。滚动容器是 `overflow-anchor: none`（钉底自动跟随所需），
  浏览器不会补偿上方内容的晚挂载，单次校正不够。用户滚轮/拖滚动条/键盘一介入
  即整体放弃校正。

### 吞吐读数收敛到服务端

TPS 改为**服务端唯一权威**：客户端只渲染 SSE 事件携带的读数（冷启动时用
`get_state` 兜底），删除整套本地累计。口径与 dsh 一手实现逐条核对一致
（解码时间不含首字延迟、只用 provider 上报的输出词元、按解码时间加权、
首字延迟取最早一步）。此前客户端的本地累计与多步加权口径不一致，读数会漂。

### 切换会话不再闪出错误思考档

切换会话瞬间档位被清空、权威值尚未返回，标签会先闪成默认值（已有会话落到
`off`）再被真实值覆盖 —— 看起来「显示变了但实际没变」。现在切换中不显示档位，
已有会话不回落到 `off`，只有新会话引导页使用设置里的默认值。

### 会话区宽度 1230 → 1100

消息列、输入栏、扩展面板、扩展 widget、todo 面板与底栏仍共用同一常量，
1920 视口实测四者同为 1100。

### 思考块与工具块改为单行

此前每个块是「一行标题 + 一行内容」两层（虚线分隔的折叠预览行），流式中也是两行。
现在**不再有独立的标题行**：

- 标签 `【思考】` / `【工具】` 内联在内容前面。折叠态与流式中整块**只有一行**
  （标签 + 内容 + 右侧耗时），块高 27–29px（实测）。
- 展开后同样不出现独立标题行：工具块的标签并进首个分区表头
  （「【工具】 命令 … 耗时」一行），思考块的标签与正文同排。
- 折叠态内容：思考块在流式中显示输出末行（随流式滚动更新），历史块只有标签；
  工具块运行中显示实时输出末行，其余显示命令行（识别调用的稳定信息）。
- 标题行原有的工具图标、工具名、状态文字不再显示；工具状态由左侧 3px 状态色边框
  表达，耗时仍在行内右侧。

## English

### Navigation rail lists every user message, jumps precisely by entryId

The rail previously read only what was rendered, so a long session showed just a
couple of entries (observed: 10 prompts listed as 2) — the timeline is lazy on
two levels (paged loading plus a trailing render window). Now:

- New `GET /api/sessions/:id/outline` extracts every user prompt on the current
  leaf path, matching the context-window semantics (prompts from other branches
  are excluded — those could not be located).
- One dash per prompt, independent of the render window; short lists stay
  centred, long lists (>320px) scroll internally so both ends stay clickable.
- Clicking asks the server to locate by entryId; the window runs from the anchor
  **through to the newest message**, so the timeline still spans
  "target → newest" and a live session's streaming tail stays attached.
- The "current prompt" highlight is derived geometrically (topmost rendered
  message, not DOM order).
- After jumping into history, "load newer messages" remains available.
- Jumps are gated by `{sessionId, leafId, jumpGeneration}`: a stale response
  cannot rewrite the timeline after switching session, branch, or double-click.

### Rail appearance and interaction

- Dashes inset 4px from the rail's left edge; gap 9 → 4px; hovered dashes turn
  dark and double in length (12 → 24px).
- The rail is only 18px wide, so the hover lengthening was clipped and produced a
  horizontal scrollbar — now two layers (outer handles vertical centring and the
  height cap while keeping `overflow: visible`, inner is the scroll container).

### Jump jank fix (main-thread busy 97% → 0–2 long tasks)

Jumping into history of a long session (1479 messages) replaces the timeline and
makes React render the whole "process details" subtree — one turn holds 40–50
messages and 47 tool calls, and three blocks alone account for 16k DOM nodes.
Measured with a fresh load before each jump:

| Jump target | Long-task total / peak | Main-thread busy | DOM nodes |
|---|---|---|---|
| Oldest | 5433ms (peak 903ms) → 170ms (peak 115ms) | 97% → 41% | 27187 → 2852 |
| Middle | 5435ms (peak 294ms) → 173ms (peak 92ms) | 96% → 81% | 10744 → 3800 |

All three targets land at `topRel = 0`, same as before — accuracy was not traded
for speed.

- Expanded "process details" content now mounts when it enters the viewport and
  unmounts when it leaves (pre-mounted 1.5 screens ahead to avoid blank areas).
  The placeholder reuses the last measured height so layout barely changes. The
  default-expanded state and the toggle are unchanged; environments without
  `IntersectionObserver` (SSR, older browsers) render eagerly.
- Scroll side: element lists are cached per render batch (no DOM query per scroll
  event) and scroll/`ResizeObserver` measurements are merged through rAF.
- Landing converges: the smooth scroll starts once layout settles, then a bounded
  correction runs (only when off by >2px, at most 12 × 100ms). The scroller uses
  `overflow-anchor: none` (needed for bottom pinning), so the browser does not
  compensate late mounts above — a single correction was not enough. Any wheel,
  scrollbar drag or key press abandons the correction entirely.

### Throughput reading converges on the server

TPS is now authoritative on the server: the client renders only the reading
carried by SSE events (with a `get_state` fallback on cold load) and the local
accumulator was removed. The semantics were checked line by line against the
dsh implementation (decode time excludes TTFT, provider-reported output tokens
only, weighted by decode time, TTFT from the earliest step).

### No more wrong thinking level flashing when switching sessions

Switching sessions briefly cleared the level before the authoritative value
arrived, so the label flashed a fallback (existing sessions fell back to `off`)
before being corrected — it looked like the level had changed. The label is now
hidden while switching, and existing sessions no longer fall back to `off`; only
the new-session guide uses the configured default.

### Chat column width 1230 → 1100

Message column, input bar, extension panel, extension widgets, todo panel and
footer continue to share one constant; on a 1920 viewport all four measure 1100.

### Thinking and tool blocks are single-line

Each block used to be two rows (a title row plus a dashed preview row), including
while streaming. There is now **no standalone title row**:

- The `【Thinking】` / `【Tool】` label is inlined before the content. Collapsed and
  while streaming the block is **exactly one row** (label + content + elapsed on
  the right), measuring 27–29px in practice.
- Expanded blocks have no standalone title row either: for tools the label merges
  into the first section header (`【Tool】 Command … elapsed`), for thinking it sits
  inline with the body.
- Collapsed content: thinking shows the last output line while streaming (and only
  the label for historical blocks); tools show the live output line while running
  and the command line otherwise.
- The tool icon, tool name and status text are no longer shown; status is conveyed
  by the 3px status-coloured left border and the elapsed time stays on the right.
