# v0.2.41

## 中文

修一个**把扩展面板变成只能看不能用**的回归（0.2.40 引入）。

### 扩展面板收不到按键

面板打开时会按 SDK 语义把焦点放到自己的键盘捕获元素（`textarea`，`focus: 'panel'` 是默认值），
而 0.2.40 里新加的按键窗口 ③ 用「焦点是否落在真实元素上」判断该不该把按键让给 DOM ——
于是面板一拿焦点，**所有按键都被判给 DOM**，插件的 `onTerminalInput` 一个键都收不到：
面板能显示，方向键/回车/空格全无反应。

修法：给面板的捕获元素加 `data-extension-keytrap` 标记，让位判定里显式排除它 ——
它不是壳的控件，拿焦点只是为了让按键有落点。壳自己的控件（拖宽手柄、子会话谱系树、
可聚焦的工具输出、输入框）仍照旧保住按键，行为不变。

反向验证：去掉排除 → 单测 1 红；还原 → 34/34。全量 2717/2717。

## English

Fixes a regression introduced in 0.2.40 that made **extension panels display-only**.

### Extension panels received no keys

When a panel opens it focuses its own key-capture element (`textarea`; `focus: 'panel'` is the default),
and the new key window ③ in 0.2.40 decides "does the DOM own this key?" from whether focus sits on a real
element — so the moment the panel took focus **every key was handed to the DOM** and the plugin's
`onTerminalInput` never fired: the panel rendered, but arrows, Enter and Space did nothing.

The key-capture element now carries a `data-extension-keytrap` marker that the yield check explicitly
excludes — it is not a shell control, it only holds focus so keys have a target. Shell controls (panel
resizers, the subagent lineage tree, a focusable tool-output block, the composer) keep their keys as before.

Reverse verification: removing the exclusion turns one unit test red; restoring it gives 34/34. Full suite 2717/2717.
