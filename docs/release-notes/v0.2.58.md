# v0.2.58

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、内核从 1.2.0 升到 1.5.0

`pi-coding-agent` 与 `pi-tui` 一起精确锁到 **1.5.0**，随包的 `pi-ai`、`pi-agent-core`、
`pi-codemode`、`pi-mcp` 同为 1.5.0，整族版本一致。engines 仍是 `>=22.19.0`，Node 要求没变。

跨过 1.3.0 / 1.4.0 / 1.5.0 三个版本，只有一条破坏性变更：**工具参数校验迁到
`@earendil-works/pi-schema`**。TypeBox 中超出 JSON Schema 的能力（`Type.Refine()`、`BigInt()`、
`Undefined()`、codecs、`Format.Set()`）对工具参数不再生效，校验失败文案从 TypeBox 的
`must have required properties path` 变成 pi-schema 的 `- path: missing`。本仓没有解析 TypeBox
文案的代码，工具错误按通用投影原样透出，自行注册的工具也没用到这些特性 —— 未命中。

### 二、这次升级修掉的、Pidance 能感觉到的行为缺陷

1. **SDK 会话里的认证走错路径**：1.2.0 的 compaction、分支摘要、bug-report 摘要会把存储的
   OAuth token 当作显式 API Key 传回模型运行时。Pidance 全部走 SDK 宿主，用 ChatGPT / Claude
   登录的用户在压缩和 `/tree` 摘要时踩的就是这条。
2. **写盘失败留下幽灵条目**：失败的会话写入会在内存留下磁盘上不存在的 entry，后续 entry 指向
   缺失的 parent，恢复后丢历史与工具。Pidance 的 JSONL 投影与「唯一 writer」假设直接依赖这条。
3. **输出截断后会话持续报错**：截断的 tool call 被丢弃但 tool result 仍保留，之后每个请求都被
   provider 拒。Web 上表现为会话突然全线失败。
4. **恢复会话丢活动工具**：1.3.0 恢复会话期间激活的工具，1.4.0 再修「分支记录了工具但扩展工具
   尚未注册」导致的失活。对应本仓的 `session-hydrate`、`session-tree-navigation`、
   `session-branch-path`。
5. **摘要被固定输出上限卡死**：长推理下 compaction / 分支摘要报 `generation hit the token cap`。
   1.4.0 起摘要使用模型输出上限，`reserveTokens` 只决定何时开始压缩 —— 设置页「为回复预留的词元
   数」的表述与 `session-context-window` 的估算口径仍然成立，因此没有改文案。

### 三、新增可用字段与目录变化

- `usage.cost.totalFromProvider`：区分账单实收与目录估算。已在本轮 31416 冒烟会话的落盘里
  确认出现（值 `false`，即目录估算）。
- `responseModel`：pi-messages 类 provider 的虚拟模型会带上真实响应模型名。
- `MarkdownTransformContext` 增加 `messageId` 与 ISO `timestamp`，渲染已存 entry 时可取。
- 内置模型目录换到 models.dev v2，实时与纯图像模型不再作为 chat 模型提供；默认 OpenAI 模型由
  `gpt-5.5` 改为 `gpt-6.1-sol`。

### 四、顺带对齐

`lib/pi-session-io.ts` 在 SDK 私有面缺失时的错误提示里写着「当前基线 0.87.0」，实际早已不是，
改为 1.5.0，避免排障时被引到错版本。

### 验收范围

定向测试 74 项（SDK host / JSONL / compaction / 主题槽位 / 渲染桥）全过；`tsc --noEmit` 无报错；
eslint 0 error（196 warning，与 0.2.57 同量）；`npm test` 2894 项全过。31416 部署后 `/api/about`
回报 `piSdkVersion: "1.5.0"`；专用测试会话跑完整一轮（模型回复 `OK`，落盘 7 条 entry，类型
`session` / `model_change` / `thinking_level_change` / `message` / `session_info`，含
`usage.cost.totalFromProvider`），会话用完即删。正式制品走隔离根 webpack 构建 + 生成前/后审计 +
tgz 安装冒烟。

桌面壳与主包同版本发布，`desktop/` 的两个版本文件已同步到 0.2.58，lockfile 里
`node_modules/@henlii/pidance` 条目 version 跟到新版、`resolved` 仍指 0.2.57 的正式 tgz。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Kernel moved from 1.2.0 to 1.5.0

`pi-coding-agent` and `pi-tui` are pinned together at **1.5.0**, with `pi-ai`, `pi-agent-core`,
`pi-codemode` and `pi-mcp` at 1.5.0 as well. engines is still `>=22.19.0`.

Across 1.3.0 / 1.4.0 / 1.5.0 there is exactly one breaking change: **tool argument validation moved
to `@earendil-works/pi-schema`**. TypeBox features outside JSON Schema (`Type.Refine()`, `BigInt()`,
`Undefined()`, codecs, `Format.Set()`) no longer apply to tool arguments, and validation failures now
read `- path: missing` instead of `must have required properties path`. No code here parses TypeBox
wording, tool errors are projected generically, and no tool registered by this repository uses those
features — the change does not apply.

### 2. Behaviour fixes that reach Pidance

1. **Wrong auth path in SDK sessions**: compaction, branch summaries and bug-report summaries passed
   the stored OAuth token back as an explicit API key. Pidance runs entirely on the SDK host, so
   users signed in with ChatGPT / Claude hit this on compaction and `/tree` summaries.
2. **Ghost entries after a failed write**: a failed session write left in-memory entries absent from
   disk, so later entries pointed at missing parents and resumed sessions lost history and tools.
   The JSONL projection and the single-writer assumption depend on this being right.
3. **Session stuck after a truncated response**: the truncated tool call was dropped while its tool
   results were kept, and every later request was rejected.
4. **Resumed sessions losing active tools**: tools activated during a session are restored since
   1.3.0, and 1.4.0 additionally fixes extension tools that the branch recorded before they were
   registered.
5. **Summaries capped by a fixed output limit**: long reasoning produced `generation hit the token
   cap`. Summaries now use the model's output limit and `reserveTokens` only decides when compaction
   starts, so the settings label and the context-window estimate stay correct and were not changed.

### 3. New fields and catalog changes

- `usage.cost.totalFromProvider` separates billed totals from catalog estimates; confirmed present in
  the smoke session's on-disk entry (value `false`, i.e. a catalog estimate).
- `responseModel` carries the real responding model for pi-messages providers.
- `MarkdownTransformContext` gained `messageId` and an ISO `timestamp`.
- The built-in model catalog moved to models.dev v2: realtime and image-only models are no longer
  offered as chat models, and the default OpenAI model changed from `gpt-5.5` to `gpt-6.1-sol`.

### 4. Unrelated alignment

`lib/pi-session-io.ts` reported "current baseline 0.87.0" in its error message for a missing SDK file
surface; it now says 1.5.0.

### Verification

74 targeted tests passed (SDK host, JSONL, compaction, theme slot, render bridge); `tsc --noEmit`
clean; eslint 0 errors (196 warnings, same count as 0.2.57); `npm test` 2894 passed. After the 31416
deploy `/api/about` reports `piSdkVersion: "1.5.0"`, and a dedicated test session completed a full
round (model replied `OK`, 7 on-disk entries of type `session` / `model_change` /
`thinking_level_change` / `message` / `session_info`, including `usage.cost.totalFromProvider`) and
was deleted afterwards. The official artifact goes through an isolated webpack build with pre/post-pack
audits and a tgz install smoke.

The desktop shell is released at the same version: both `desktop/` version files say 0.2.58, and the
`node_modules/@henlii/pidance` lock entry moved its version while `resolved` still points at the
0.2.57 tarball.
