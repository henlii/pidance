# v0.2.48

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。本版是 v0.2.47 之后的一批面板与删除路径修复。

### 插件面板：方向键/回车终于能到插件

`ExtensionCustomPanel` 的焦点副作用两个分支都调了 `blur()`，焦点因此落在 `BODY` ——
插件组件的 `handleInput()` 收不到任何按键，面板看起来「点不动、选不了」：ask_user_question
的选项无法切换，也就选不出「Type something.」那一项。

现在按服务端给的 `request.focus` 分派：`panel`（或缺省）聚焦面板的 keytrap，
只有 `editor` / `none` 才让出；手机端维持不抢焦点（软键盘会盖住面板）。
实测：焦点落在 `TEXTAREA.extension-panel-keytrap`，↓↓ 可移动选中项，「Type something」后
直接打字即可（`❯ 3. h` → `❯ 3. hi`）。

### 面板内部还原为插件自己的渲染

停用面板内部的行级语义网页化（issue #114：边框换 CSS 细线、加粗标题换 HTML 标题、
选项换可点按钮）与网页输入框（issue #116 的呈现那半）—— 面板内容与输入都交回插件自己控制。
两处实现都保留在代码里，恢复只需把 `webViewEnabled` 改回判断式、并把
`<input data-extension-input>` 放回来。

### 半屏面板高度：内容驱动，上限是隐藏输入区后的一半

之前半屏插槽写死 `flex: 0 0 33.3333%`：内容只有两三行也照样占满三分之一（看着像块空板），
而且固定高度会把面板底部的输入行裁到可视区外。现在改成 `flex: 0 1 auto` +
`max-height: 50%`（面板激活时输入区已隐藏，根容器 = 会话区 + 面板，所以 50% 就是视觉上一半），
面板本体 `height: auto`（全屏仍占满），内容超过上限才由面板内部滚动。
实测（1280×760）：面板 362px、会话区 362px。

### 删除会话不再因活动面板挂起

现象：删除一个正开着插件面板的会话时，删除永久挂起，之后连 abort 都被拒
（`Session is being deleted`），面板选项点不动 —— 那个会话就卡死了。

根因：面板的 `ctx.ui.custom()` promise 只有插件组件自己结束才 resolve；它不 resolve
→ 那次工具调用不返回 → agent run 结束不了 → `deleteSession` 的 `destroyAsync` 一直等它，
而原流程只发 `abort`，没动这个面板。

修法：删除前先发新命令 `extension_ui_cancel_active`，host 读活动面板快照的 id 并送 **Esc**。
用 Esc 而不是 Ctrl+C 有实测依据：按 `lib/extension-panel-keys.ts` 的口径，插件界面显示时
Esc 归插件（关面板/退出选择态），Ctrl+C 是壳的「中断运行」—— 第一版发 `\x03` 时返回了
`cancelled: true` 但 rpiv-ask-user 的面板并不结束（running 集合仍在），换 Esc 后立刻清空。

实测：带活动 ask 面板的会话直接删除（不手动 abort），修复前 80s 超时，修复后 0s 成功。

### 验收范围

`tsc --noEmit`；`npm test` 2772 项；31416 无头浏览器实测：面板焦点与按键链路、
半屏面板几何（1:1 且内容驱动）、带面板会话的删除耗时。

## English

Package `@henlii/pidance`, CLI `pidance` only. A batch of panel and delete-path fixes on top of v0.2.47.

### Plugin panels: arrow keys and Enter finally reach the plugin

`ExtensionCustomPanel`'s focus effect called `blur()` in both branches, leaving focus on `BODY` —
the plugin component's `handleInput()` received nothing, so the panel looked dead:
ask_user_question's options could not be moved, which also meant "Type something." was unreachable.

It now dispatches on the server-provided `request.focus`: `panel` (or absent) focuses the panel's
keytrap, only `editor` / `none` give focus up; mobile keeps the no-focus-steal behaviour (the soft
keyboard would cover the panel). Measured: focus lands on `TEXTAREA.extension-panel-keytrap`,
↓↓ moves the selection, and after choosing "Type something" typing just works
(`❯ 3. h` → `❯ 3. hi`).

### Panel internals render exactly what the plugin drew

Line-level semantic "webifying" (issue #114: box-drawing borders to CSS rules, bold titles to HTML
headings, options to clickable buttons) and the web input for pi-tui's Input primitive
(issue #116's presentation half) are both disabled — content and input belong to the plugin again.
Both implementations stay in the tree; restoring them means flipping `webViewEnabled` back and
putting `<input data-extension-input>` back.

### Half-screen panel: content-driven height, capped at half of the visible area

The half-screen slot was pinned to `flex: 0 0 33.3333%`, so a three-line panel still filled a third
of the screen (and the fixed height also clipped the panel's own input row out of view). It is now
`flex: 0 1 auto` + `max-height: 50%` (with the composer hidden, the root is conversation + panel,
so 50% is half of what you see), the panel body is `height: auto` (full-screen still fills), and
scrolling starts only past the cap. Measured at 1280×760: panel 362px, conversation 362px.

### Deleting a session no longer hangs on an active panel

Symptom: deleting a session that has a plugin panel open hung forever; afterwards even abort was
refused (`Session is being deleted`) and the panel was unresponsive — the session was stuck.

Cause: the panel's `ctx.ui.custom()` promise only resolves when the plugin's component finishes;
until then the tool call never returns, the agent run never ends, and `destroyAsync` waits forever.
The delete path only sent `abort` and never touched the panel.

Fix: before aborting, the delete path now sends a new `extension_ui_cancel_active` command; the host
reads the active panel snapshot and delivers **Esc**. Esc rather than Ctrl+C is an empirical choice:
per `lib/extension-panel-keys.ts`, Esc belongs to the plugin while its UI is up (close panel / leave
selection state) whereas Ctrl+C is the shell's "interrupt run" — the first version sent `\x03`,
reported `cancelled: true`, and rpiv-ask-user's panel stayed open (running set unchanged); with Esc
the running set cleared immediately.

Measured: deleting a session with an active ask panel (without a manual abort): 80s timeout before,
0s success after.
