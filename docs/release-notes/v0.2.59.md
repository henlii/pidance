# v0.2.59

## 中文

包名 `@henlii/pidance`，CLI 仅 `pidance`。

### 一、项目拖放改成指针事件，手机端可用

旧实现用 HTML5 `draggable` + `dragstart/dragover/drop`：触摸端根本不触发，手机上项目行拖不动；
桌面端只有「整行覆盖即落点」，没有插入位置反馈，落点也只在目标行上闪一条线。

现在统一走 Pointer Events（鼠标 / 触摸 / 笔同一路径）：

- 鼠标、笔：按下后位移超过 5px 起拖；触摸：长按 240ms 起拖，长按未成立就移动按滚动处理（10px 阈值）。
- 起拖后由列表容器上的非被动 `touchmove` 拦下浏览器滚动（只挂侧栏列表，正文区不进这条同步路径）；
  上下 44px 边缘带自动滚动；系统手势接管（`pointercancel`、切后台）整次拖拽作废，不提交顺序。
- 松手按落点提交顺序；本次拖拽吞掉浏览器补发的 click，不再顺带折叠/展开项目。
- 落点：项目行上半/下半决定插到目标前还是后；指针落在某个项目展开的会话区时固定落到该项目之后
  （此前按「最近行距」判定，指针偏上偏下会给出两种等价但视觉在跳的指示线）；拖回自己的会话区不显示落点。
- 视觉：被拖行留在原位当虚线占位槽（不做 translateY 让位——项目行与它自己的会话行同处一个 wrapper，
  行一让位就会压在仍在文档流的被拖行上）；浮动标签起拖浮起、松手缩回；目标行画 2px 插入线；
  落定行保留 480ms 高亮。`prefers-reduced-motion` 下关闭动画。
- 键盘：项目行 `Alt+↑/↓` 换位，`aria-live` 播报「已移到第 N/M 位」。

### 二、跨进程会话跟随（文件级）

两个实例共享 `~/.pi/agent/sessions`，但 live 事件只在持有 running lease 的进程内存里；另一个实例打开
同一会话时 `/api/agent/<id>/events` 返回 404，界面停在打开那一刻。

- 新增只读探测 `GET /api/sessions/[id]/tail`：`offset`+`ino` 判增量，`wait` 长轮询（最长 10s，
  一个在途请求就是一份订阅，客户端 abort 即退订，服务端不维护全局 watch 表），返回
  `localLive` / `writerActive` / `lastEntryId` / `changed` / `reset` / `externalRewrite`。
- 客户端三态互斥：本进程有 live host 时让 SSE 独占时间线；没有 host 时按文件增量合并（投影复用
  已有的 `/api/sessions/[id]/context?after=<entryId>`）；`reset` 走静默全量重载。
- 守卫：后台标签不跟随、跳读窗口不覆盖、正在翻历史时让路；追加被跳过时不推进基线，下一轮把增量补回。
- 外部改写保护：writer 活着却检测到文件截断或换 inode 判 `externalRewrite`，不静默合并并给出提示——
  否则内存里的条目会在下次 append 把用户的改动写回。
- 粒度：Pi 只在 `message_end` 与各种 `append*` 操作时落一行，所以文件跟随到消息/工具结果边界，
  不是逐字流；逐字仍需持有端导出事件。
- 顺带：只读（子代理）会话按 run 记录 `subagent-runs-changed` 静默跟随尾页（600ms 防抖、
  失败只记控制台、不把正文换成错误页）。

## English

Package `@henlii/pidance`, CLI `pidance` only.

### 1. Project drag-and-drop is now pointer-based and works on touch devices

The old implementation used HTML5 `draggable` + `dragstart/dragover/drop`: touch devices never fired
those events, so projects could not be dragged on a phone, and the desktop drop target was the whole row
with no insertion feedback.

Everything now goes through Pointer Events (mouse, touch and pen share one path):

- Mouse/pen start dragging after 5px of movement; touch starts after a 240ms long-press, and moving
  before that is treated as scrolling (10px threshold).
- While dragging, a non-passive `touchmove` listener on the sidebar list blocks browser scrolling;
  44px edge bands auto-scroll; `pointercancel` / backgrounding aborts the drag without committing.
- Releasing commits the order at the drop point; the synthetic click that follows a drag is swallowed.
- Drop position: the upper/lower half of a project row decides before/after. Inside an expanded project's
  session area the target is always "after that project" (previously the nearest-row heuristic produced two
  equivalent but visually jumping indicators); dragging back into your own session area shows no indicator.
- Visuals: the dragged row stays in place as a dashed placeholder (no translateY shifting — project rows and
  their session rows share one wrapper, so shifting overlaps the row still in flow), a floating label lifts
  on drag start and shrinks on drop, the target row draws a 2px insertion line, the settled row stays
  highlighted for 480ms. Animations are disabled under `prefers-reduced-motion`.
- Keyboard: `Alt+↑/↓` reorders a focused project row and an `aria-live` region announces the new position.

### 2. Cross-process session follow (file level)

Two instances share `~/.pi/agent/sessions`, but live events only exist in the process that holds the running
lease; opening the same session in the other instance returned 404 from `/api/agent/<id>/events` and the UI
froze at the moment it was opened.

- New read-only probe `GET /api/sessions/[id]/tail`: `offset`+`ino` detect growth, `wait` long-polls up to
  10s (one in-flight request is one subscription; aborting it unsubscribes). It reports
  `localLive` / `writerActive` / `lastEntryId` / `changed` / `reset` / `externalRewrite`.
- Three mutually exclusive states: with a local live host the per-session SSE owns the timeline; without one
  the client merges file increments (projection reuses `/api/sessions/[id]/context?after=<entryId>`);
  `reset` triggers a silent full reload.
- Guards: hidden tabs do not follow, jump windows are not overwritten, ongoing history paging wins; a skipped
  append does not advance the baseline, so the increment is retried.
- External-rewrite protection: a live writer combined with truncation or an inode change yields
  `externalRewrite` instead of a silent merge, because the in-memory entry tree would otherwise write the
  user's edit back on the next append.
- Granularity: Pi persists one line per `message_end` and per `append*` operation, so file following reaches
  message/tool-result boundaries, not per-token streaming.
- Also: read-only (subagent) sessions follow their run record via `subagent-runs-changed` with a 600ms
  debounce, logging failures instead of replacing the transcript with an error page.
