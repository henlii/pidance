# v0.2.42

## 中文

修一个**让插件选择/问卷面板只能看不能用**的回归（0.2.40 引入，0.2.41 没修对）。

### 面板收不到按键（真实原因）

0.2.40 新增的按键窗口 ③ 在 **window 捕获阶段**监听：只要它判定「这个键该给插件」，就
`preventDefault + stopPropagation`，并把键作为 `terminal_input` 只送给插件的**全局**监听器
（`onTerminalInput`）。

而插件面板的组件（问卷、选择、审批这类）按键走的是**另一条路**：面板自己的键盘捕获元素把键
转成终端序列，经 `extension_ui_input` 直接送进组件的 `handleInput`。窗口 ③ 抢在它前面，组件
就一个键都收不到 —— 现象是面板显示正常、方向键和回车完全没反应。

0.2.41 我判反了方向：把面板的捕获元素从「归 DOM」里排除，等于让窗口 ③ 抢得更彻底。本版反过来 ——
面板自己的元素**算归 DOM**（它有自己那条到组件的通路），窗口 ③ 不插手；窗口 ③ 继续服务于
「面板开着但焦点不在它身上」的场景。

实机复验（31416，真实的 ask-user 问卷面板）：`选中 1. 苹果` → 方向键 → `选中 2. 香蕉` →
回车 → `面板已关`，两次发出的都是 `extension_ui_input`。反向验证：去掉判定 → 单测 1 红；还原 → 34/34。

## English

Fixes a regression (introduced in 0.2.40, still present in 0.2.41) that made **plugin select/questionnaire panels display-only**.

### Why panels received no keys

0.2.40 added key window ③, which listens in the **window capture phase**: when it decides a key belongs
to the plugin it calls `preventDefault + stopPropagation` and delivers the key as `terminal_input` to the
plugin's **global** listeners (`onTerminalInput`) only.

A plugin panel's *component* (questionnaire, select, approval) is fed through a different path: the panel's
own key-capture element converts the key into a terminal sequence and sends it via `extension_ui_input`
straight into the component's `handleInput`. Window ③ cut in first, so the component never saw a key — the
panel rendered fine and arrows/Enter did nothing.

0.2.41 guessed the wrong direction (excluding the panel's capture element from "DOM owned" let window ③
intercept even more). This release inverts it: the panel's own element **counts as DOM-owned** (it has its
own path to the component) and window ③ stays out; window ③ keeps serving the "panel is open but focus is
elsewhere" case.

Live re-verification (31416, the real ask-user questionnaire): `selected 1. 苹果` → ArrowDown → `selected
2. 香蕉` → Enter → `panel closed`, each sending `extension_ui_input`. Reverse verification: removing the
check turns one unit test red; restoring it gives 34/34.
